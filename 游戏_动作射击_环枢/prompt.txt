【交付形态】
产物为一个标准 HTML5 单文件（例如 index.html），CSS 与 JavaScript 全部内联，不得引用任何外部 CDN、外部脚本、外部样式表、外部字体、外部图片、外部音视频，不得使用 iframe 与 srcdoc，不得使用 Base64 内嵌图片来代替绘制。页面在 1536×864 视口下必须完整呈现且不出现滚动条；其余常见视口（1280×720、1440×900、1920×1080）允许弹性重排，但所有仪表与画布不得互相遮挡、不得溢出容器。整个界面由五块物理独立的绘图面构成：一块主战场画布（呈现环带内部侧视剖面）、一块横贯底部的仪表带画布、一块自转矢量罗盘画布、一块桁架疲劳寿命环画布、一块环带阵图雷达画布。所有图形必须由绘图指令逐帧实时绘制，不得使用预渲染位图或图像素材。界面底色为深空蓝黑，主强调色为青（cyan）、副强调色为琥珀（amber），危险态转红，谐次态转紫，成功态转绿。整个游戏必须由固定种子 20261001 驱动，同一部机器、同一浏览器、同一种子下重新载入必须得到逐项完全一致的环带几何、桁架阵列与波次编排。

【玩法闭环】
玩家在环带内以「停下换增益、加速换穿透、机动换生存」三选一的节奏推进：静止压回 350 ms 完成环带同调，解锁跳跃与蓄能重弹并把谐振增益一路爬满；同调完成后可以靠跳跃登上桁架、以桁架为掩体与落脚点；但一旦移动，谐振增益单向衰减、同调标记消失，必须重新压回。与此同时，四类敌对实体的免疫关系由当前环速唯一决定，玩家必须通过三路出力滑杆实时改写环速：把环速拉高可以同时打开同步门禁与共振窗，却会同步放大离心重力、恶化弹道侧偏、压低弹速与机动速度，并持续累积超转压力；把环速压低则门禁与共振窗一起关闭，但角色与弹丸都更轻快。每次击穿敌实体本身不产生资源，资源只从两个渠道回流：命中敌实体核心区（竖直方向的窄带）回充少量反应堆出力与装甲，以及在敌实体贴近涌入孔时用被门禁封堵的射击换回充——也就是说「打不动」这件事本身是有收益的。敌对实体抵达配电枢纽造成漏防，同一波内累计三次漏防即触发涌流侵入，谐次窗整体降频、环速被外源强行拖拽、三孔同时加投，玩家必须立刻降速而不是提速才能重新对上窗口。超转压力越限触发超转锁死，操作权被短暂收走，输入全部被拒绝，但世界照常推进、敌实体照常漏防，因此玩家必须在压力爬到上限之前主动把环速出力撤回。装甲熔穿触发破舱回溯，实体阵列与角色位置在当帧复位、装甲与弹匣补满，但账本、漏防、超转与桁架脱开计数一律保留，回溯预算用尽后再次破舱将直接进入结算。八波打满且场中实体清空即进入账本结算，全部读数由逐帧写入的事件账本一次性归约得出，给出逐项得分、综合倍率与星级。

【第二层：六大环形强耦合子系统】[扩展要求 (origin="augmented")]
以下六个子系统必须在同一帧内互相读写彼此的状态，任一子系统的改变必须在同一帧内被其余至少两个子系统感知并在画面上留下可观察的证据，禁止把它们写成互不相干的独立模块。
子系统一「环速整定」：三路出力（环速 / 武器 / 伺服）之和恒等于 100%，滑杆必须联动收敛；环速出力唯一决定目标角速度，实测角速度以带转动惯性的方式向其逼近，且转动惯量本身随当前角速度升高而增大——越转越难改。实测角速度向下游输出四个派生量：离心重力、科里奥利强度、谐次门禁开闭、超转压力累积率。
子系统二「谐次门禁」：四类敌对实体各自绑定一个谐次中心与一个窗口半宽，同步体在环速离开其谐次窗口时变得可击穿，共振体在环速落进其谐次窗口时才变得可击穿，反旋体恒双倍易伤，驻旋体无门禁。门禁关闭时弹丸被吞噬、不产生伤害，但计入「门禁封堵」并回充反应堆出力；在涌入孔附近发生的门禁封堵回充量加倍。谐次窗的中心频率不是一个常量——它会随涌流子系统的状态整体平移。
子系统三「科里奥利弹道」：弹丸在旋转参考系中承受与其水平速度成正比的横向加速度，方向由旋转方向与航向共同决定，因此顺环射击与逆环射击的弹道弯曲方向相反；同一门枪在环速升高时下坠更猛、在环速降低时更接近直线。敌方弹幕同样受此偏转。该子系统的输出直接改变命中判定点，从而反向影响门禁子系统的封堵与穿透统计。
子系统四「承重衰变」：桁架段被角色落身冲击、被弹丸误伤时累积疲劳；疲劳按固定速率自行衰减并按寿命比例映射到寿命环；寿命归零时桁架整段脱开，脱开事件同时改写主战场画面、阵图计数与寿命环三处。角色站在桁架边缘的窄带内保持静止会持续扣减反应堆出力（离线驻留扣减），形成一个「站着不动既涨同调增益又掉储备」的直接对冲。
子系统五「反应堆与出力账本」：反应堆出力与装甲在角色静止、待机、移动时绝不自然回复，只由命中敌实体核心区与门禁封堵两个渠道回充；三路出力的总量受反应堆出力约束；超转压力越限时整本账目被抽税。账本是逐帧追加的事件数组，是所有统计与最终结算的唯一真值来源。
子系统六「涌流与漏防」：敌对实体抵达配电枢纽造成漏防并扣除枢纽余量；同一波内漏防累积到三次触发涌流侵入，涌流把谐次窗中心整体降频、把实测环速强行拖向低值、额外加投一批混型实体，并在此期间持续给超转压力加码。涌流结束后谐次窗复位，但已造成的漏防、已消耗的枢纽余量与已写入账本的事件不会被撤销。

【第四层：仪表视窗、复合手势与核心难点】
左侧栏自上而下三个仪表视窗：一「自转矢量罗盘」，指针给出当前角速度方向与量值，外圈用刻度表明谐次窗位置，下方逐行给出目标环速、实测环速、转动惯性滞后，以及由符号前缀标出的门禁开闭结论；二「出力三路分配」，三条滑杆分别控制环速、武器、伺服，三值之和恒为 100% 且拖动任一条时其余两条必须按比例收敛，滑杆下方逐行给出反应堆出力与三路占比；三「实时损耗率监视器」，逐行给出桁架结构损耗率、离线驻留扣减率、能量转换状态与超转压力速率，并在三项均为零时把能量转换状态标为「稳定」。左侧栏最下方是「环带事件流」视窗，以倒序滚动列表实时回放最近若干条账本事件，每条按语义着色（收益绿 / 惩戒红 / 状态青），静止时显示「等待事件」。右侧栏自上而下三个模块：一「桁架疲劳寿命环」，以 T-01 ~ T-14 共十四枚编号圆环阵列给出全部桁架段的当前寿命，未落位时整册改写为「待落位」占位文字与标定进度，疲劳中的段按寿命比例变色，已脱开的段整段消失；二「环带阵图 · 军情」，标题行给出「桁架 已落位数 / 总数 · 敌 场中实体数」，环形拓扑图标出涌入孔、泄压缝、配电枢纽与本体的相对位置，下方逐行给出本体航向、涌入孔门禁、场中敌实体与歼 / 漏计数、配电枢纽余量、装甲与弹匣；三「历史收益倍率账本」，十一行常驻计分项（锚定同调完成、核心区命中、命中弹数、歼灭敌实体、门禁封堵、环向冲刺 / 反转、超转锁死、破舱回溯、桁架脱开、弹丸误伤桁架、综合收益倍率）在非结算态下必须十一行全部可见、不得被面板高度裁切，因此该列表所在容器必须随面板高度撑满；结算态下该列表改用同一容器扩展为十八行含加权分值的完整账目，超出可见高度的部分以容器内滚动的方式呈现，不得静默丢弃后面的行。底部仪表带横向分四区：一「速度矢量仪」给出实测环速、离心重力、科里奥利系数、弹速、伺服跑速、跳跃初速与航向夹角；二「动能示波雷达」，用双色历史曲线同时描绘超转压力与装甲完整度的时间轨迹，采样必须与固定步长推进同源，从而在时间冻结后仍可复现；三「超转压力标尺」，给出横向压力条、硬直剩余、过载次数、蓄能张力与反应堆出力；四「八阶状态流转带」，八个状态段逐帧高亮当前状态，其下三行给出当前状态全名与状态机原因、环带时钟与账本事件数与回溯进度、世界坐标与环带周长与场中实体与弹丸数。最底一行状态带给出状态、种子、环带时钟、账本事件数、回溯进度、距下次涌流、本体航向、场中敌实体与歼 / 漏、配电枢纽余量、装甲与弹匣、世界坐标、环速与离心重力。

必须支持的复合交互手势（每一帧必须能被独立观察到）：一「走位中连射」——按住方向键与射击键，弹丸在科里奥利侧偏下需玩家自行补偿；二「跳跃后落身加载」——起跳需要同调完成，落地时按冲击速度给桁架加载疲劳，冲击越大疲劳越多；三「静止蓄能」——保持相对静止的同时按住蓄能键，同调环与蓄能张力必须同时可见地爬升；四「冲刺接反转」——环向冲刺改变推进节奏，紧急反转环向把角速度方向掉头并随即改写门禁结论与弹道弯曲方向；五「三路实时重分配」——在交战中途拖动三条滑杆，离心重力、弹速、跑速、跳跃初速与门禁结论必须在同一帧内全部跟着变；六「门禁封堵换回充」——故意对免疫中的实体开火，弹丸被吞噬但反应堆出力上升，且靠近涌入孔时上升更快；七「登桁架避险」——起跳后落在桁架上，桁架顶面既是落脚点也是掩体，但落身会消耗它的寿命。

四个核心难点：其一，环速是唯一同时控制「穿透能力」与「自身重量」的旋钮，玩家必须在同一根滑杆上完成攻防取舍；其二，同调增益只在绝对静止时累积、一移动就单向衰减、一受击就立刻清零，而站在桁架边缘静止又会持续扣减储备，形成三方对冲；其三，谐次窗中心不是常量，涌流会把整套窗口整体降频，玩家必须把「提速打开门禁」的直觉反过来用；其四，超转锁死与破舱回溯两种惩罚的语义完全不同——前者收走操作权但保留战场进度，后者在当帧重置战场但保留账本，玩家必须据此决定何时主动降速、何时主动放弃一个回合。

【抗直觉断言与自动化探针】
以下断言必须可被外部脚本在不读取实现源码的前提下、仅通过可编程接口与像素采样验证：
断言一：把三路出力的任意一条拉到 100，其余两条必须自动收敛到 0，且三者之和在任意时刻恒为 100；连续拖动一万次后仍不得出现和值偏离。
断言二：在角色接地且速度为零的前提下推进时间到同调阈值之前，跳跃必须无效；越过阈值之后同一输入必须使角色离地，且离地高度随伺服出力单调增。
断言三：把环速调到同步体谐次窗口内，对同步体射击必须不造成任何伤害但必须使「门禁封堵」计数增加、反应堆出力上升；把环速推离窗口后，同一目标必须立刻开始掉血。
断言四：把环速调进共振体的共振窗，对共振体射击必须造成伤害；把环速拉到窗口之外，同一目标必须恢复免疫。窗口中心在涌流期间必须整体平移，且平移方向必须是降频。
断言五：装甲完整度在角色静止、行走、跳跃、待机各四百帧内必须逐帧不增；只有命中敌实体核心区与发生门禁封堵两种情形能让它上升。
断言六：把超转压力人为置到上限后推进一帧，状态必须在同一帧内变为锁死、全部输入被拒绝、同调环与谐振增益必须在同一帧内被清空，但同时场中敌实体数量与配电枢纽余量必须继续朝恶化方向变化。
断言七：触发一次破舱回溯后，账本条目数、漏防累计数、超转次数与桁架脱开数必须与回溯前逐项相等；而装甲与弹匣必须在同一帧内回到满值、场中实体必须清零、角色必须回到最后一次安全落点。
断言八：对某一段桁架连续加载疲劳直至寿命归零，该段必须在同一帧内从主战场画面、阵图的已落位计数与寿命环三处同时消失，且此后不得再参与落身判定。
断言九：把超转压力与装甲的时间轨迹在时间冻结状态下重新采样，必须与冻结前推进同样步数所得轨迹逐点相同。
断言十：结算面板的每一项数值必须能在账本事件数组中一一对应地回溯出原始事件；把账本人为清空后重新结算，必须得到全零评分与一星。
断言十一：页面加载后六十秒内不得出现任何未捕获的 JavaScript 异常或页面级错误；控制台不得输出错误级日志。
断言十二：在同一种子下重载页面两次，桁架编号与位置、涌入孔位、泄压缝位、波次主型与数量必须逐项完全一致；寿命环的编号圆环数必须恒为十四枚。

【第五层：交付边界与绝对禁止项】
必须做到：所有绘制都由代码实时生成；三路出力滑杆之和恒等于 100%；八阶状态机严格互斥且流转带逐帧同步；事件账本是唯一真值来源；固定种子下完全确定性；时间冻结后仍能单步复现；界面在 1536×864 下无滚动条、无遮挡、无文字截断；寿命环与阵图给出的桁架总数必须恒为十四，且与统计条所写的段数逐字一致。
绝对禁止：使用任何外部资源（CDN、外链脚本、外链样式、外链字体、外链图片、音视频）；使用 iframe 或 srcdoc；把图形以 Base64 位图方式内嵌；使用表格或纯 CSS 拼出主战场而不做逐帧绘制；把敌对实体的免疫关系写成随机的或由计时器翻转的，而不由环速谐次唯一决定；把超转锁死实现成全局暂停；把破舱回溯实现成连账本一起清空；把破舱回溯实现成延后若干帧才复位；把反应堆出力或装甲实现成随时间自动回复；把三路出力的和值放任偏离 100%；把结算数值写成独立的累加计数器而不从账本归约；把桁架数量写成随生成结果浮动的可变值；在帧率无关的地方使用变步长积分导致同种子不同结果；出现任何未捕获异常、控制台错误、占位文字或未实现分支。
