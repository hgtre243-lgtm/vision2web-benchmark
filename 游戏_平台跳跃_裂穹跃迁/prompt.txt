# 裂穹跃迁 RIFTVAULT LEAP —— 单文件可交互仿真关卡

## 第 1 层 · 任务背景与系统定位

你需要在**一个标准自包含 .html 文件**内，实现一个名为「裂穹跃迁」的竖井攀爬式平台跳跃仿真。全部样式与脚本必须内联，不得引用任何外部资源。

场景设定：一座深度数千世界单位的垂直矿脉竖井。井壁为暗紫岩层，其上悬浮着若干**矿壳浮屿**——它们是唯一的落脚点。浮屿不是静态平台：它们会被冲击压沉、会回弹、会在承受超过极限的损耗后碎裂并永久消失。竖井内存在**随高度与时间变化的切变风场**。玩家操控一台单座跃迁舱，自井底向上跃迁，直到抵达最高矿壳或坠入井底。

本关卡的验收对象**不是画面美观度**，而是一套**多子系统强耦合的动力学系统**是否被真实实现。任何试图用「固定动画 + 状态标志位」蒙混的实现都会在下列行为级验收中暴露。

## 第 2 层 · 核心机制与环形耦合子系统

必须实现**不少于 5 个互相制约的子系统**，且它们构成一个**闭环**：A 产生的数据制约 B，B 消耗 C，C 的阈值熔断 D，D 的结算结果决定 E，E 又反过来改写 A 的输入。至少包含：

1. **浮屿承重衰变力学**——每座浮屿维护独立的**下沉位移**与**下沉速率**。浮屿受到冲击后产生下沉，其**峰值下沉量与冲击瞬间下落速度的平方成正比**（不是线性、不是开方）。下沉后按弹性阻尼规律回弹收敛。当累积损耗越过该浮屿的独立承载极限时，浮屿进入**碎裂坍缩**。
2. **切变风场矢量**——井内存在水平与垂直两个分量的**非均匀矢量场**。关键约束：**同一时刻，不同高度的风向可以完全相反**。因此「顺风／逆风」不是全局属性，而是**与位置相关的局部量**。风场必须按位置与时间连续求解，禁止分段常量。
3. **能量索张力摆荡**——跃迁舱可在空中向斜上方最近的矿壳**锚定能量索**，形成单摆约束。索的**应变**由重力分量与离心分量共同决定；应变越限触发告警，越限更深则索断裂。拉索动作会额外注入应变。
4. **动能同调蓄能**——跃迁能力**不是落地即恢复**。舱体必须在矿壳上把**归一化线速度压到极低阈值以下并持续驻留**，同调等级才逐级充能。同调等级直接决定起跳初速与收益倍率。
5. **多维因果计费账本**——逐帧累积一条**时序样本序列**，记录每一帧的速度、风场分量、索应变、同调等级、当前浮屿下沉量、冲击增量、落点偏差等原始量。结算时的三项指标**必须由该序列在结算时刻回溯聚合得出**。
6. **磁极相位切换**（可并入上述任一子系统）——舱体与浮屿之间存在可切换的极性关系，使邻近浮屿由排斥转为吸附，**惯性守恒但受力方向反转**。

**环形闭合要求**：浮屿下沉改变可锚定几何 → 几何改变能量索摆荡的初始条件 → 摆荡应变熔断决定同调是否清零 → 同调等级门控起跳初速 → 起跳冲击载荷回写浮屿下沉与损耗 → 账本汇总上述全部。**任何一环被写成常量或绕过，判定该系统未实现。**

## 第 3 层 · 显式有限状态机

必须实现**不少于 8 个互斥状态**，且**严禁用若干全局布尔变量的组合来隐式决定行为**。状态必须由一个**单一枚举字段**承载，每一次进入状态都要执行明确的进入动作。至少覆盖下表全部状态：

| 状态名 | 前置守卫 Guard | 触发源 Trigger | 转移目标 Next State | 系统副作用 Action |
|---|---|---|---|---|
| `ANCHOR_IDLE` 驻台停泊 | 舱体与某浮屿保持接触且同调尚未开始充能 | 触地当帧 | `ATTUNE_CHARGING` | 标记该浮屿为承载中；启动承重积分 |
| `ATTUNE_CHARGING` 接触同调充能 | 仍接触浮屿且归一化线速度低于静止阈值 | 驻留计时逐帧推进 | `ATTUNE_READY` / `ANCHOR_IDLE` | 累加同调计时；速度一旦越阈则计时**快速回退** |
| `ATTUNE_READY` 同调满级待发 | 同调计时已满且仍接触浮屿 | 计时到达满值 | `CHARGE_SPRINT` / `AIRBORNE_BALLISTIC` | 解锁跃迁与蓄力；点亮收益倍率 |
| `CHARGE_SPRINT` 长按蓄力冲刺 | 同调满级、接触浮屿、蓄力键按下 | 蓄力键按下 | `AIRBORNE_BALLISTIC` | 蓄力档位逐帧推进并锁定同调；抬手瞬间释放冲量并清空同调 |
| `AIRBORNE_BALLISTIC` 空中弹道飞行 | 舱体与所有浮屿均不接触、未挂索 | 离台当帧 | `CRUST_SINK` / `AIRBORNE_BRAKE` / `TETHER_SWING` / `SLIP_FAIL` | 记录起跳事件与弹道预测落点；持续积分风场 |
| `AIRBORNE_BRAKE` 空中受阻速降 | 空中且正按住与当前运动方向**相反**的方向键 | 反向键按下 | `AIRBORNE_BALLISTIC` / `SLIP_FAIL` | 水平速度被强阻尼压制；**垂直下坠加速度反而增大** |
| `TETHER_SWING` 索张力摆荡 | 空中且能量索已锚定 | 锚定成功 | `TETHER_STRAIN` / `AIRBORNE_BALLISTIC` | 施加单摆约束；按切向速度与索长求解应变 |
| `TETHER_STRAIN` 索应变告警 | 索已锚定且应变越过告警阈 | 应变越阈 | `TETHER_SWING` / `AIRBORNE_BALLISTIC` | 索身光学告警；越限更深则断裂并抛射舱体 |
| `CRUST_SINK` 矿壳承重下沉 | 接触浮屿且该浮屿瞬时下沉量越过可视阈 | 重冲击落台 | `CRUST_FRACTURE` / `ATTUNE_CHARGING` / `ANCHOR_IDLE` | 浮屿按弹性阻尼回摆；承载读数实时刷新 |
| `CRUST_FRACTURE` 矿壳碎裂坍缩 | 某浮屿引信走完或损耗越过承载极限 | 引信到期 | `AIRBORNE_BALLISTIC` / `SLIP_FAIL` | 浮屿解体坠落、从可碰撞集合移除、计入账本损耗 |
| `SLIP_FAIL` 坠入井底 | 舱体纵坐标越过井底警戒线 | 越线当帧 | `RUN_SETTLE` | 冻结操控；记录失败原因 |
| `RUN_SETTLE` 跃迁结算 | 主动结算或任一失败终止 | 结算触发 | 重新跃迁 | 冻结物理；由时序序列回溯聚合三项指标并渲染结算面板 |

**状态互斥性要求**：任一帧内 `state` 字段只能取上表中的一个值；状态转移必须在事件日志中留痕（形如 `STATE → 状态名`），日志只增不减。

## 第 4 层 · 行为因果回路与反直觉陷阱

### 4.1 复合手势（不少于 5 组）

1. **长按蓄力冲刺**——驻台同调满级后**按住**冲刺键蓄力，蓄力档位随时间推进；抬手瞬间释放，获得与档位成正比的**水平冲量与抬升**，同时**清空同调**。
2. **空中反向受阻速降**——空中按住与运动方向相反的方向键：水平速度被强阻尼压制，**垂直下坠反而加快**（用于快速切入下方矿壳）。
3. **张力索拉扯解脱**——摆荡中反向拉索使应变陡增；在**固定窗口内二次拉索**可主动解脱，并获得沿切向的弹射初速。窗口外二次拉索只累加应变，不解脱。
4. **磁极相位瞬切**——瞬切极性使邻近浮屿由排斥转为吸附；**惯性守恒，受力方向反转**。存在冷却时间，冷却期内瞬切必须被拒绝并在日志中留痕。
5. **同调脉冲释放**——同调满级后起跳，在**极短窗口内二次触发**跃迁键可释放同调脉冲：叠加一次向上爆发初速，**但清空同调并使本次落台冲击对浮屿的损耗翻倍**。

### 4.2 反直觉阻尼规则（不少于 3 条，均为强制的验收点）

- **陷阱 T1 · 接触同调时延**——**触地绝不立即刷新跃迁能力**。舱体必须把归一化线速度压到 **0.05 以下并持续驻留不少于 350 毫秒**，同调才开始满级。着陆瞬间按跳跃键必须**无效**。速度一旦越阈，计时必须以**快于充能的速度回退**。空中同调必须清零。
- **陷阱 T2 · 顺风反而更慢**——舱体与气流**同向**时，阻力被**非线性放大**（水平阻力上限提升约 40%），起跳初速被压制；舱体与气流**反向**时反而获得**上升气流升力**。这意味着「借助风力跳得更远」在本关卡中是**错误直觉**。
- **陷阱 T3 · 反冲发生在离台而不是落地**——冲击瞬间浮屿只**下沉**，不弹跳。向上反冲位移**只在舱体脱离浮屿的瞬间**产生，反冲系数为 **0.68**（即反冲位移为冲击下沉量的 0.68 倍），并且**同一次脱离同时点燃 500 毫秒引信**：引信走完该浮屿必然碎裂坍缩。这意味着「在同一个浮屿上反复起跳」是被系统禁止的策略。
- **陷阱 T4 · 风是切变风**——同一时刻不同高度风向可完全相反；界面上必须同时给出**水平切变分量**与**垂直气流分量**的实时读数，并标注当前是「顺风·同向」「逆风·反向」还是「静风/驻台」。

### 4.3 两阶段确认

- **跃迁两阶段**：第一阶段「驻台同调」必须完整达成，第二阶段「长按蓄力→释放」或「起跳→短窗口内脉冲」才生效。任一阶段缺失，第二阶段的输入必须被吞掉（而非降级生效）。
- **解脱两阶段**：第一阶段「首次拉索」只累积应变，第二阶段「窗口内二次拉索」才解脱；窗口外操作必须降级为普通拉索。

### 4.4 失败重试闭环

坠入井底、浮屿全部碎裂、主动结算三条路径都必须进入结算态。结算态必须显示**三个指标 + 结算原因 + 本次回溯的帧样本数**，并提供**重新跃迁**入口；重新跃迁后世界重新生成但**随机种子保持不变**（同一台机器上两次重新跃迁的浮屿布局必须逐位一致），账本清零。

### 4.5 结算口径（写死数值直接判零）

结算面板上的三项指标必须**全部由一个逐帧累积的时序样本序列在结算时刻回溯聚合**得出：

- **跃迁效率**：回溯每一次起跳事件，取起跳瞬间的同调等级，做加权均值。
- **落点偏离**：回溯每一次落地事件，取该次起跳时预测落点与真实落点的差值绝对值，做聚合。
- **矿壳损耗率**：回溯全部冲击增量，计算**已碎裂浮屿所吸收的冲击积分**占**总冲击积分**的比例。

**硬性判定**：若实现中这三项由任意常量、任意与帧序列无关的计数器、或任意「看起来合理」的公式直接产出，本题判零。结算面板必须同时标注本次参与聚合的**逐帧样本条数**，该条数必须等于物理帧数组的实际长度。

### 4.6 能量守恒约束

**舱体在静止状态与无操作状态下，动能与同调资源绝不自然恢复**。驻台静止时不得出现任何自发速度增长；无输入时不得出现跳跃计数、碎裂计数、解脱计数的自发增长。

## 第 5 层 · 技术边界与绝对禁止项

**允许**：单个自包含 .html 文件；内联样式与内联脚本；程序化绘制的矢量图形（含渐变、阴影、粒子）。

**绝对禁止**：

1. 禁止任何外部网络资源——不得出现外部样式表、外部脚本、外部字体、外部图片、嵌入式子文档框架。
2. 禁止位图资源——所有视觉元素必须由代码绘制。
3. 禁止在题面实现中使用任何**具名缓动函数**或**现成插值公式**（如各类具名缓动曲线、现成抛物线解析式、现成样条插值）；一切运动必须由**逐帧力／加速度积分**产生。
4. 禁止硬编码像素常数来伪造物理——下沉量、反冲量、弹道高度、应变值必须由状态量实时求解。
5. 禁止用弹窗类阻塞接口做交互反馈，禁止向文档流写入内容。
6. 禁止把状态判定写成若干全局布尔量的组合；必须是单一枚举 + 显式转移表。
7. 禁止在静止状态恢复动能或同调。

**渲染架构硬约束**：

- 主视口、仪表阵列、井道雷达**必须是三块相互独立的渲染画布**，各自拥有独立的重绘节拍与独立的绘制逻辑，但**共享同一份内存物理态**。禁止用单画布分区绘制冒充多画布。
- 主视口必须在 1440×900 视口下无横向与纵向溢出；在 1280 / 1024 / 900 / 768 / 414 / 375 宽度下均不得出现溢出，且主画布必须保持可见且尺寸充足。
- 分辨率缩放必须自适应设备像素比，画布不得出现模糊或拉伸。

**仪表硬约束**：必须提供**不少于 5 组独立仪表**，至少包含：风向罗盘（同时指示水平与垂直分量）、动能示波条（对归一化速度做**时序**波形，非瞬时数值）、浮屿稳定性环形标尺（指示承载余量）、重力矢量仪（指示即时有效重力方向与是否被升力／受阻抑制）、收益倍率表（逐项列出当前生效的倍率与其依据）。仪表读数必须**随物理态实时刷新**，禁止使用占位数值。

**运行质量硬约束**：页面启动后**控制台不得出现任何未捕获异常、任何资源加载失败、任何脚本错误**；持续运行不得崩溃；渲染循环必须稳定在 40 帧/秒以上。

**交付物**：一个 .html 文件，外加一组连续状态的参考截图（1440×900）。题面描述与实现必须完全自洽——任何一处「题面说了但实现没做」或「实现做了但题面没说」都视为不通过。
