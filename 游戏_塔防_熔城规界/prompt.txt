━━ 四、零散落全局变量与 ArrayBuffer 状态 ━━
1. 全部运行时代码包在**单个 IIFE** 内；脚本顶层不得散落游戏逻辑全局变量。只允许一个引擎实例（如 `FORGE`）承载全部运行时状态，对外只暴露只读探针、渲染入口与调试接口。
2. 核心数值态必须放在**同一块** `ArrayBuffer(65536)` 上，用 `Int32Array` / `Float32Array` / `Uint8Array` 三种视图访问；整型与浮点分视图、按固定槽位读写，不得用普通对象数组保存逐帧实体。
3. 固定内存映射（不得改名改址，探针按此读取）：
   `TICK=0, STAGE=1, STAGE_T=2, SCORE=3, LIFE=4, FRAMES=5, KEYS_HEAD=6, KEYS_TAIL=7`；
   按键环 `RING=64`，共 256 个 Int32 单元；
   玩家 `PX=600, PY=601, PZ=602, PVX=603, PVY=604, PVZ=605, PKINE=606, PSTAB=607, PCHARGE=608, PATTUNE=609, POFF=610, PIMPACT=611`；
   敌体槽 `EBASE=1024, ESTRIDE=8, ECAP=128`；塔槽 `TBASE=5120, TSTRIDE=8, TCAP=64`。
4. 实体用槽位 + 视图 + 空闲栈管理；每帧不得为每个实体新建对象。渲染层可以读槽位并画图，但不得反向写第二份真值。
5. 所有随机量由固定种子驱动的确定性 PRNG 产生（如 mulberry32），禁止 `Math.random`、时间戳、系统熵。
6. 内存中的 `TICK` 只由物理步递增；重绘次数、窗口缩放、鼠标移动都不得改变它。

━━ 五、五阶段确定性启动流水线 ━━
全部耗时以 60Hz 定长帧计，阶段只能顺序推进，严禁跳步、并行或按墙钟跳过。

| 阶段 | 标识 | 时长 | 画面与硬性内容 | 出口 |
|---|---|---|---|---|
| 0 | `POST_RAM_CHECK` | 72 帧 / 1.20 s | 复古 BIOS 自检控制台；逐行输出内存、音频、噪声、PRNG 检测；右侧 MEMORY MAP | 帧满 → 1 |
| 1 | `PALETTE_BAKING` | 84 帧 / 1.40 s | 离屏烘焙 Sheet A（4-bit 索引）与 Sheet B（16 色映射）；像素进度 0→100% | 帧满 → 2 |
| 2 | `CHIP_AUDIO_WARMUP` | 54 帧 / 0.90 s | 双脉冲振荡器 + 白噪声缓冲预热，440→880Hz / 150ms | 帧满 → 3 |
| 3 | `ATTRACT_TITLE` | 常驻 | Logo、呼吸提示、自动寻路演示；等待投币或空格 | 投币/空格 → 4 |
| 4 | `STAGE_INTRO_LOCK` | 180 帧 / 3.00 s | 3-2-1-GO；物理与位移锁定；视差与呼吸运行；棋盘显影 | 帧满 → PLAYING |

阶段 0 必须出现以下三串，逐字一致：
`VRAM ALLOC: 0x8000 OK`
`AUDIO_CORE: DUAL_PULSE OK`
`PRNG SEED BOUND: OK`
同时至少显示 `FORGE MERIDIAN HAL V2.09`、`COPYRIGHT 1989 MERIDIAN WORKS`、`VRAM MAP: A000-BFFF OK`、`VRAM REFRESH: 60HZ OK`、`AUDIO IRQ: 60HZ OK`、`NOISE GEN: LFSR-17 OK`。底部左 `POST 1.20S · NO FAULTS`，右 `FRAME n/72`。右侧内存映射四项：`VRAM 0x8000`、`RING 256W`、`SHEET 2/2`、`SEED LOCK`。

阶段 1：在内存中创建两张 256×64 离屏画布；Sheet A 每像素写 `index×17` 的灰阶，Sheet B 用固定 16 色表映射同一索引；精灵格 16×16，布局为 `WARDEN×4`、四类敌各 ×2（含 BOSS）、三类塔各 ×2；总 8 个精灵定义。进度条必须由**逐像素/逐精灵写入进度**驱动，不是定时假动画。图注必须出现 `SHEET A 256×64 · 4096 BYTES · 4BIT` 与 `PALETTE SWAP 16/16 · NO EXTERNAL IMAGE`。

阶段 2：`AudioContext` 中创建恰好两个 `OscillatorNode`（`square`，基频 440 与 220）与一个白噪声 `AudioBufferSourceNode`；噪声缓冲用 LFSR-17 生成，不用外部音频。主增益 0→0.22→0 包络，第一振荡器 440→880Hz 指数扫频 150ms，第二振荡器同步 440→880Hz。音频失败不得中断启动。

阶段 3：Auto-pilot 演示必须真实运行：固定航点自动移动熔核，自动建塔、自动开波，形成可读的攻防画面；标题层覆盖其上但不遮挡顶栏、左右栏。`INSERT COIN / PRESS SPACE` 明暗呼吸，周期严格 1.0 s，透明度在 0.55–1.00 之间。演示账本独立，投币后重置为正式局读数。

阶段 4：倒计时按 `3 → 2 → 1 → GO` 推进；期间物理、位移、波次全部冻结，但视差、粒子与呼吸继续；棋盘按种子逐格显影到 100%；输入写入环形缓冲但暂不执行。满 180 帧后切换 `PLAYING`，并给出第 1 波 8 秒预告。

━━ 六、纯软件 5×7 点阵字库 ━━
- 每个字形 7 行 × 5 位位掩码，bit4 为最左像素；`A–Z`、`0–9` 与常用符号（`. , : ; - + / \ % ( ) [ ] < > = ! ? * # & ' " _ | @ ~ ^ · × → ≡ Σ ≥ ◀`）必须齐备，空格为全 0。
- 光栅化流程：清空离屏条带 → 逐像素 `fillRect(1×1)` 写前景色 → `drawImage` 放大到目标字号；放大前后都必须 `imageSmoothingEnabled = false`，保证硬边像素。
- 字宽 5、字距 1，步进 6 像素；对齐支持 left / center / right；基线以 `y - 7×scale` 计算。任意字号只能整数倍最近邻放大。
- 所有画布文本转为大写；中文不进入点阵字库。
- 验收会 grep：画布渲染路径中不得出现 `ctx.font`、`fillText`、`strokeText`（注释除外）。

━━ 八、六个环形强耦合子系统 ━━
1. 地脉准线相位：相位在 `[0,1)` 推进，一周切四段，交替取两个互异常值斜率；两斜率之和为 2、之积为 1/2，解析周期 26 s。前半程导内环、后半程导外环；同时输出射程倍率 `1+0.18cos(2πφ)` 与敌速倍率 `1−0.22cos(2πφ)`，两者严格反相。跨段必须做时间切分，不得用单段斜率代替整帧。每次跨 0、0.5 边界产生换相事件并计数。
2. 瞄准锥伺服与落空：每塔维护瞄准角，逐帧向准线角缓动；角差先归一化到 `[−π, π)` 再比较。只有目标方位与瞄准角之差 < 该塔锥半角才命中，超出即落空并写事件流。锥半角与射程实时读取结渣折减。
3. 热力—结渣—重铸：开火积热、持续散热；越过上限即过热，射速压低直到回落。过热与漏怪累积结渣；结渣按比例折减全场射程、收窄锥半角，并让后续波次额外加派魔物。花费 120 炉金发动重铸脉冲：清空结渣并锁定相位 6 s（脉冲持续 1.6 s）。
4. 地块衰变与反作用：每格有完整度与沉陷；塔与熔核都会加载。落地冲击越大，沉陷越深、完整度损失越大；完整度 ≤ 0.02 转失稳，≤ 0 碎裂为不可站立虚空，格上塔一并坠毁并写事件流。未失稳格完整度随时间自然衰变；相邻格沉陷同帧互相可见。失稳格自熔核离块起算 500 ms 引信，到期碎裂。离块瞬间地块反向弹起，弹跳/离块速度比固定 0.68，只在离块触发。
5. 炉芯耦合与同调：只有站上或建在炉芯八邻格才累积耦合；耦合 ≥ 60 后该塔伤害 ×1.35。落点分核心区（格宽居中 20%）与边缘区（外侧 62%）：核心区按离差加权返还 46 动能并退还该格塔 26 积热；边缘区按每秒 5% 持续扣稳定度。落块后必须相对静止满 350 ms 才恢复跃迁次数。
6. 逐帧审计账本：每帧 22 列样本（时间戳、坐标、高度、动能、稳定度、炉壁、结渣、均温、击杀、漏怪、相位、塔数、在场数、在场总血、开火、累计伤害、地块均完整度、耦合达标塔数、本帧离差、守恒缺口、风切强度）。结算五项与三张主指标卡必须由该数组纯函数回溯聚合，帧样本数恒等于数组长度；无落点样本时「落点精准」判为无定义并标注 `NO DATA` / `—`，不得以满值冒充。

━━ 九、五科目整数守恒账（不得旁路） ━━
五科目：炉金 / 熔铁 / 动能 / 结渣 / 熵损，全部整数记账（1 点资源 = 100 单位）。建造、升级、出售、击杀赏金、伤害入账、蓄能/翻转/摆荡/制动的动能变化、共振、兑换、置换、提前出波——全部走**同一条双边转账函数**，从一科目扣、向另一科目加。恒等式：五科目之和恒等于 `1000000`，守恒缺口恒为 `0`。该等式逐帧落入账本第 21 列，并在底部账本画布以比例带 + 逐科目整数 + Σ + 缺口四段显示。严禁直接改写单科目余额。

━━ 十、七画布与仪表 ━━
七块画布独立取景、独立重绘、共享同一份 ArrayBuffer 物理态：
A `cvWorld`：棋盘/管网/节点/塔/锥/弹/怪/熔核/粒子/世界叠加层；
B `cvRig`：动态 HUD 四象限仪表，逐帧；
C `cvRadar`：相位指针、敌情、熔核方位、结渣峰值；

仪表不少于十五项：气流矢量罗盘、地块寿命环、蓄能槽、损耗率监视器、倍率示波六行、结渣槽、相位指针盘、波次情报六行、状态决策表十四行、账本网格六项、守恒比例带、事件流、顶栏八读数（任务号/种子、相位、炉壁、炉金、动能/稳定度、波次、状态枚举、得分）、熔核读数、结算三卡。所有读数逐帧刷新，不得静态占位。

━━ 十二、硬件级测试探针硬握手协议 ━━
必须暴露 `window.__V2W_GAME_HARNESS__`，对象常驻，不得依赖调试开关：
1. `getStage()`：只返回六个字符串之一——`"POST_RAM_CHECK"`、`"PALETTE_BAKING"`、`"ATTRACT_TITLE"`、`"STAGE_INTRO"`、`"PLAYING"`、`"GAME_OVER"`。映射：HAL 阶段 0 → `POST_RAM_CHECK`；阶段 1 与 2 → `PALETTE_BAKING`（`CHIP_AUDIO_WARMUP` 不单列）；阶段 3 → `ATTRACT_TITLE`；阶段 4 或入场态 → `STAGE_INTRO`；已结算 → `GAME_OVER`；其余运行态 → `PLAYING`。
2. `injectScanCode(scanCode, isDown)`：把扫描码写入内部 256 单元环形缓冲，**不得 dispatch 伪造键盘事件**。JAMMA 映射：`1=UP, 2=DOWN, 4=LEFT, 8=RIGHT, 16=BUTTON_A, 32=BUTTON_B, 64=COIN/START`。单元打包为 `((scanCode & 127) << 1) | (isDown ? 1 : 0)`；返回当前环深度。非法输入不得破坏缓冲。
3. `step(frameCount)`：进入确定性步进模式并冻结 rAF 逻辑推进；执行 `frameCount` 次 `tick(1/60)`，随后重绘七画布与 DOM；返回 `TICK`。`step(0)` 只重绘、不推进、不改变校验和。
4. `getStateChecksum()`：严格返回
   `((tickCount * 31) ^ (playerX * 17) ^ (playerY * 13) ^ score) >>> 0`
   其中 `tickCount`、`score` 取 Int32 槽，`playerX`、`playerY` 取 Float32 槽；冻结不动时连续调用必须恒定。
5. 可选诊断项：`getStageFrame()`、`getRingDepth()`、`getMemory()`、`getBootLog()`；不得影响上述四项契约。
6. 扫描码在每帧 `tick` 开头统一排空；投币在 `ATTRACT_TITLE` 直接进入 `STAGE_INTRO`，空格同效。探针注入 180 帧后必须进入 `PLAYING`，且 `getStage()` 始终落在六串枚举内。
7. 渲染循环与确定性循环分离：rAF 只负责常规画面；`step` 必须能在页面被后台节流时仍按参数推进。

━━ 十三、红线 ━━
- 禁止外部资源、内联远程字体、data 图片冒充程序化资源、网络请求与 eval 加载。
- 禁止把游戏状态散落为顶层 `var`/`window.xxx`；唯一引擎实例之外只保留常量与探针。
- 禁止画布原生文字；禁止系统字体栅格化；禁止用 DOM 文本覆盖画布再截图冒充点阵。
- 禁止跳阶段、压缩时长、用 CSS 动画伪造启动进度、用定时器跳过烘焙或音频。
- 禁止假事件派发、假键盘事件、直接改 DOM 键盘状态绕过环形缓冲。
- 禁止用现成缓动替代逐帧速度—加速度积分；禁止固定常数伪造风场。
- 禁止 `Math.random`、`Date.now` 参与物理或动画相位；禁止非确定性的实体遍历顺序。
- 禁止占位读数、写死文案、只改顶栏不改账本的第二真值。
