━━ 四、零散落全局变量与 ArrayBuffer 状态 ━━
1. 全部运行时代码包在**单个 IIFE** 内；脚本顶层不得散落游戏逻辑全局变量。只允许一个引擎实例承载全部运行时状态，对外只暴露只读探针、渲染入口与调试接口。
2. 核心数值态必须放在**同一块** `ArrayBuffer(65536)` 上，用 `Int32Array` / `Float32Array` / `Uint8Array` 三种视图访问；整型与浮点分视图、按固定槽位读写，不得用普通对象数组保存逐帧实体。
3. 固定内存映射（不得改名改址，探针按此读取）：
   `TICK=0, STAGE=1, STAGE_T=2, SCORE=3, LIFE=4, FRAMES=5, KEYS_HEAD=6, KEYS_TAIL=7`；
   按键环 `RING=64`，共 256 个 Int32 单元；
   玩家 `PX=600, PY=601, PZ=602, PVX=603, PVY=604, PVZ=605, PKINE=606, PSTAB=607, PCHARGE=608, PATTUNE=609, POFF=610, PIMPACT=611`；
   敌体槽 `EBASE=1024, ESTRIDE=8, ECAP=128`；塔槽 `TBASE=5120, TSTRIDE=8, TCAP=64`。
4. 实体用槽位 + 视图 + 空闲栈管理；每帧不得为每个实体新建对象。渲染层可以读槽位并画图，但不得反向写第二份真值。
5. 所有随机量由固定种子驱动的确定性 PRNG 产生（mulberry32），禁止 `Math.random`、时间戳、系统熵。
6. 内存中的 `TICK` 只由物理步递增；重绘次数、窗口缩放、鼠标移动都不得改变它。

━━ 六、纯软件 5×7 点阵字库 ━━
- 每个字形 7 行 × 5 位位掩码，bit4 为最左像素；`A–Z`、`0–9` 与常用符号（`. , : ; - + / \ % ( ) [ ] < > = ! ? * # & ' " _ | @ ~ ^ · × → ≡ Σ ≥ ◀`）必须齐备，空格为全 0。
- 光栅化流程：清空离屏条带 → 逐像素 `fillRect(1×1)` 写前景色 → `drawImage` 放大到目标字号；放大前后都必须 `imageSmoothingEnabled = false`，保证硬边像素。
- 字宽 5、字距 1，步进 6 像素；对齐支持 left / center / right；基线以 `y - 7×scale` 计算。任意字号只能整数倍最近邻放大。
- 所有画布文本转为大写；中文不进入点阵字库。
- 验收会 grep：画布渲染路径中不得出现 `ctx.font`、`fillText`、`strokeText`（注释除外）。

映射：HAL 0/1/2 → 前三项；HAL 3 → 按 autoStep 取 AUTO_SCOUT/AUTO_BUILD/AUTO_WAVE；HAL 4 → INTRO_SEGMENT；正式局结算 → LIVE_SETTLE；无敌人且契约正常 → LIVE_PATROL；有敌人 → LIVE_ENGAGE；契约宽限期后达标且需补塔 → LIVE_CONTRACT；保持率跌破 80% → LIVE_REPAIR。每次跃迁计数并写入最近 24 条轨迹。

━━ 八、九个强耦合子系统 ━━
1. 地脉准线相位：相位在 `[0,1)` 推进，一周切四段，交替取两个互异常值斜率；两斜率之和为 2、之积为 1/2，解析周期 26 s。前半程导内环、后半程导外环；同时输出射程倍率 `1+0.18cos(2πφ)` 与敌速倍率 `1−0.22cos(2πφ)`，两者严格反相。跨段必须做时间切分，不得用单段斜率代替整帧。每次跨 0、0.5 边界产生换相事件并计数。
2. 瞄准锥伺服与落空：每塔维护瞄准角，逐帧向准线角缓动；角差先归一化到 `[−π, π)` 再比较。只有目标方位与瞄准角之差 < 该塔锥半角才命中，超出即落空并写事件流。锥半角与射程实时读取结渣折减。
3. 塔体伺服锁定：每塔维护 0–1 的锁定度，有目标时以 `1.85/s × (1−0.35×结渣/100)` 上升，无目标或过热时以 `1.60/s` 衰减。锁定度 ≥ 0.34 才允许击发；未达标时只累积、不开火。塔体四模式 `IDLE / SLEW / LOCK / VENT` 与锁定弧同屏显示，右栏给出「锁定 n · 均 x%」。
4. 热力—结渣—重铸：开火积热、持续散热；越过上限即过热（VENT），射速压低直到回落。过热与漏怪累积结渣；结渣按比例折减全场射程、收窄锥半角，并让后续波次额外加派魔物。花费 120 炉金发动重铸脉冲：清空结渣并锁定相位 6 s（脉冲持续 1.6 s）。
5. 地块衰变与反作用：每格有完整度与沉陷；塔与熔核都会加载。落地冲击越大，沉陷越深、完整度损失越大；完整度 ≤ 0.02 转失稳，≤ 0 碎裂为不可站立虚空，格上塔一并坠毁并写事件流。未失稳格完整度随时间自然衰变；相邻格沉陷同帧互相可见。失稳格自熔核离块起算 500 ms 引信，到期碎裂。离块瞬间地块反向弹起，弹跳/离块速度比固定 0.68，只在离块触发。
6. 炉芯耦合与同调：只有站上或建在炉芯八邻格才累积耦合；耦合 ≥ 60 后该塔伤害 ×1.35。落点分核心区（格宽居中 20%）与边缘区（外侧 62%）：核心区按离差加权返还 46 动能并退还该格塔 26 积热；边缘区按每秒 5% 持续扣稳定度。落块后必须相对静止满 350 ms 才恢复跃迁次数。
7. 相位契约：每 13.0 s 签发一张，交替要求内环或外环**一邻域内至少 2 座塔**。宽限 1.5 s 后开始统计保持率；到时保持率 ≥ 80% 判达成，炉金 +45、动能 +6、连约 +1 并刷新最佳连约；否则判违约，结渣 +5、连约清零。契约条第 23 列写入账本并在主视窗左上常驻 `CONTRACT INNER/OUTER n/2 · HOLD x% · 剩余 S · STREAK n`。
8. 护送护壳：每波队列末尾三只非王单位带壳。壳量 `34 × (1 + 0.08 × (波次−1))`；壳在时本体只承受 45% 伤害，折光塔对壳造成 2.4 倍剥离；壳归零时记一次 `shellsBroken` 并爆散，本体恢复全额受伤。护壳数、剥离数同时进入顶栏、右栏与账本第 24 列。
9. 逐帧审计账本：每帧 26 列样本（时间戳、坐标、高度、动能、稳定度、炉壁、结渣、均温、击杀、漏怪、相位、塔数、在场数、在场总血、开火、累计伤害、地块均完整度、耦合达标塔数、本帧离差、守恒缺口、风切强度、契约保持率、在场护壳数、塔均锁定度、微状态索引）。结算五项与三张主指标卡必须由该数组纯函数回溯聚合，帧样本数恒等于数组长度；无落点样本时「落点精准」判为无定义并标注 `NO DATA` / `—`，不得以满值冒充。

━━ 九、五科目整数守恒账（不得旁路） ━━
五科目：炉金 / 熔铁 / 动能 / 结渣 / 熵损，全部整数记账（1 点资源 = 100 单位）。建造、升级、出售、击杀赏金、伤害入账、蓄能/翻转/摆荡/制动的动能变化、共振、兑换、置换、提前出波、契约奖励/惩罚、护壳剥离——全部走**同一条双边转账函数**，从一科目扣、向另一科目加。恒等式：五科目之和恒等于 `1000000`，守恒缺口恒为 `0`。该等式逐帧落入账本第 21 列，并在底部账本画布以比例带 + 逐科目整数 + Σ + 缺口四段显示。严禁直接改写单科目余额。

━━ 十二、硬件级测试探针硬握手协议 ━━
必须暴露 `window.__V2W_GAME_HARNESS__`，对象常驻，不得依赖调试开关：
1. `getStage()`：只返回六个字符串之一——`"POST_RAM_CHECK"`、`"PALETTE_BAKING"`、`"ATTRACT_TITLE"`、`"STAGE_INTRO"`、`"PLAYING"`、`"GAME_OVER"`。映射：HAL 阶段 0 → `POST_RAM_CHECK`；阶段 1 与 2 → `PALETTE_BAKING`；阶段 3 → `ATTRACT_TITLE`；阶段 4 或入场态 → `STAGE_INTRO`；已结算 → `GAME_OVER`；其余运行态 → `PLAYING`。
2. `injectScanCode(scanCode, isDown)`：把扫描码写入内部 256 单元环形缓冲，**不得 dispatch 伪造键盘事件**。JAMMA 映射：`1=UP, 2=DOWN, 4=LEFT, 8=RIGHT, 16=BUTTON_A, 32=BUTTON_B, 64=COIN/START`。单元打包为 `((scanCode & 127) << 1) | (isDown ? 1 : 0)`；返回当前环深度。非法输入不得破坏缓冲。
3. `step(frameCount)`：进入确定性步进模式并冻结 rAF 逻辑推进；执行 `frameCount` 次 `tick(1/60)`，随后重绘七画布与 DOM；返回 `TICK`。`step(0)` 只重绘、不推进、不改变校验和。
4. `getStateChecksum()`：严格返回
   `((tickCount * 31) ^ (playerX * 17) ^ (playerY * 13) ^ score) >>> 0`
   其中 `tickCount`、`score` 取 Int32 槽，`playerX`、`playerY` 取 Float32 槽；冻结不动时连续调用必须恒定。
5. 诊断项至少包括：`getStageFrame()`、`getRingDepth()`、`getMemory()`、`getBootLog()`、`getBakeStats()`、`getContract()`、`getMicro()`、`getShells()`、`getInvariants()`、`selfTest()`、`getStateChecksum()`；不得影响上述四项契约。
6. 扫描码在每帧 `tick` 开头统一排空；投币在 `ATTRACT_TITLE` 直接进入 `STAGE_INTRO`，空格同效。探针注入 180 帧后必须进入 `PLAYING`，且 `getStage()` 始终落在六串枚举内。
7. 渲染循环与确定性循环分离：rAF 只负责常规画面；`step` 必须能在页面被后台节流时仍按参数推进。调试赋值（炉金、结渣、契约、波次）也必须走守恒转账或显式受限路径，不得制造第二真值。

━━ 十三、红线 ━━
- 禁止外部资源、内联远程字体、data 图片冒充程序化资源、网络请求与 eval 加载。
- 禁止把游戏状态散落为顶层 `var`/`window.xxx`；唯一引擎实例之外只保留常量与探针。
- 禁止画布原生文字；禁止系统字体栅格化；禁止用 DOM 文本覆盖画布再截图冒充点阵。
- 禁止跳阶段、压缩时长、用 CSS 动画伪造启动进度、用定时器跳过烘焙或音频。
- 禁止假事件派发、假键盘事件、直接改 DOM 键盘状态绕过环形缓冲。
- 禁止用现成缓动替代逐帧速度—加速度积分；禁止固定常数伪造风场。
- 禁止 `Math.random`、`Date.now` 参与物理或动画相位；禁止非确定性的实体遍历顺序。
- 禁止占位读数、写死文案、只改顶栏不改账本的第二真值；禁止在截图中手写读数。
