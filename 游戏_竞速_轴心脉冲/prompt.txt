请严格依据随附的 8 张参考图，实现一个名为「轴心脉冲 AXELPULSE」的俯视环形漂移竞速游戏。产物为单个自包含 .html 文件，CSS 与 JS 全部内联，双击即可在浏览器中打开，并直接运行于 1280×720 的 #stage 舞台上（更高分辨率下整舞台等比放大，内部坐标系不变）。

世界由一条闭合的非欧环形赛道构成：赛道半径随极角连续起伏（闭合极坐标环，不允许用折线段近似），带宽恒定；横截面被切成 5 条同心环带，每条环带拥有各自的摩擦系数、风剪倍率与感应强度，三条物理量沿「轴心环 → 内切线 → 中线带 → 外切线 → 真空带」严格单调变化。环道划分为 24 段浮屿板，每段板有独立的完好度与寿命引信，被击碎或引信烧尽后坠入不可站立的虚空。车辆以极坐标推进，横向位置落在哪条环带，就实时继承该带的全部动力学与配额规则。环道内缘之内是轴心区，外缘之外是外真空区，两者均不可通行。速度以 km/h 显示，圈次上限 10 圈。

操作仅使用键盘：方向键或 WASD 转向与油门/刹车，另有 10 个高阶手势键（手刹漂移、浮空跃迁、长按蓄能弹射、空间相位翻转、能量索抓取摆荡、浮屿共振同调脉冲、动量下压速坠冲击、竞速功兑换入、牵引储备兑换出、分带配额置换）。每个手势的作用对象与代价都必须真实存在，不可做成无副作用的快捷按钮。主循环必须使用固定步长 1/60 s 的确定性积分，不得使用与真实时间耦合的可变 dt。

════════════════════════════════════════
一、硬件抽象层（HAL）与零全局约束
════════════════════════════════════════
1. 全部代码包在单个 IIFE 内。全局只允许存在两个名字：window.AXELPULSE（游戏 API）与 window.__V2W_GAME_HARNESS__（压测探针）。不得挂载任何调试变量、状态对象、计时器句柄或缓存表。
2. 所有核心状态必须落在一块 65536 字节的 ArrayBuffer 上，且只通过三个视图读写：
   - Int32Array(HAL.AB)  → 整数槽位；
   - Uint8Array(HAL.AB)  → 字节视图；
   - Float32Array(HAL.AB, 2048) → 浮点槽位，必须从字节偏移 2048 起。
   整数槽位至少包含：TICK=0、STAGE=1、SCORE=2、PX=3、PY=4、LIFE=5、STAB=6、FATIGUE=7、STRAIN=8、LAP=9、GAP=10、HEAD=11、TAIL=12、KEYQ=32。浮点槽位至少包含：PX=0、PY=1、VX=2、VY=3、TH=4、U=5、ALT=6、VZ=7、T=8、CHARGE=9。
   玩家坐标以 ×100 定点落在整数槽，速度、角度、高度、蓄能走浮点槽；G.score / G.lap / G.life / G.stab / G.fatigue / G.strain / G.chargeM 必须由这些槽位的访问器承载，不得另存一份影子变量。
   注意：整数槽 LAP=9 与浮点槽 CHARGE=9 分属两个视图，互不相干；任何把蓄能写进整数视图的实现都会覆盖圈数，属于硬错误。
3. 按键队列必须是 256 字的环形缓冲，元素打包为 ((scanCode & 127) << 1) | down，head/tail 存在整数槽 HEAD/TAIL。写入不得伪造 DOM 键盘事件，也不得依赖真实焦点。
4. 画布文本一律使用内置 5×7 位图字库：不得出现 ctx.font、ctx.fillText、ctx.strokeText、ctx.measureText 或任何 .font 赋值。字符表至少覆盖 A–Z、0–9、空格与常用标点；小写统一转大写；缺字符号只允许用 '?' 占位，但成品画面上不得真的出现由未翻译汉字退化而来的 '?'。
5. 字形必须离屏栅格化并缓存为位图画布（imageSmoothingEnabled=false），同一文本/颜色/倍率只生成一次。对齐语义由文本颜色与 c.textAlign 决定：left/center/right 均在绘制函数内部换算成左上角坐标；y 参数表示文本底边，实际绘制于 y−7×scale。
6. 画布上的中文必须先经替换表译成 ASCII 再栅格化。替换表按「键长降序」排序后逐条替换，避免短词吃掉长词（例如「轴心」先于「轴心环」命中）。替换后再把残余非 ASCII 字符降到 '?'。DOM 覆盖层的文字可以保留中文，但六块 canvas 上不得残留任何汉字或 '?'。

════════════════════════════════════════
二、五阶段确定性启动（帧数精确，逐帧可复算）
════════════════════════════════════════
启动不是一段进度条动画，而是五个互斥阶段。每阶段有独立帧计数 HAL.frame，进入下一阶段时清零。整条链路由 tick(1/60) 驱动，rAF 只负责重绘。

阶段 1　POST_RAM_CHECK（72 帧，约 1.2 s）
- 全屏自检终端画面：标题 POST_RAM_CHECK，右上角实时打印「STAGE 0 / FRAME nn / 72」。
- 逐行打印且必须逐字包含以下三条：`VRAM ALLOC: 0x8000 OK`、`AUDIO_CORE: DUAL_PULSE OK`、`PRNG SEED BOUND: OK`。
- 其余自检行至少覆盖：HYDROSTAT BIOS 2.6 / ARCADE HARDWARE、CPU: 68000 COMPAT / 60 HZ FIXED TICK、RAM CHECK 64K、PALETTE RAM 16 X RGB444、NOISE LFSR-17、SHEET A 4-BIT INDEXED、SHEET B PALETTE SWAP X16、JAMMA 7-BIT SCAN RING、DETERMINISTIC CLOCK 1/60、ATTRACT PATHFINDER、BOOT COMPLETE / HAND OFF TO BAKING。
- 底部必须有内存转储行，首行字节可读为 AXELPULSE 的 ASCII 码，证明 64 KiB 缓冲确实存在且被写过。
- 第 72 帧结束，切 PALETTE_BAKING，帧计数归零。

阶段 2　PALETTE_ASSET_BAKING（84 帧；探针枚举名为 PALETTE_BAKING）
- 屏幕标题 PALETTE_ASSET_BAKING；左右两栏。
- Sheet A：4 位索引色，必须现场画出角色 4 帧（FRAME 1..4）、一行 4 个敌人（ENEMY）、以及 8×2 共 16 块地形砖；帧序与砖块随烘焙进度逐格点亮，未完成帧保持暗色。
- Sheet B：16 色调色板交换，必须画出 16 个色块，并叠加一条扫描线把上半区做明度偏移，证明调色板交换真实发生。
- 像素进度条从 0 走到 100%，旁边大字打印 `BAKING nn%`。
- 底部注明 `64K ARRAYBUFFER / 256-WORD SCAN RING / 0 EXTERNAL FETCH`，并左右打印各表状态（SHEET A OK / SHEET B / PALETTE）。
- 第 84 帧结束，切 CHIP_AUDIO_WARMUP，帧计数归零。

阶段 3　CHIP_AUDIO_WARMUP（54 帧）
- 屏幕标题 CHIP_AUDIO_WARMUP，副标题 `2 X PULSE OSCILLATOR + 1 X WHITE NOISE SOURCE`。
- 音频必须真实建立：两个方波 OscillatorNode（占空比 50% 与 25%）加一个白噪声 AudioBufferSourceNode（线性反馈移位寄存器生成样本）。
- 两个振荡器在 150 ms 内同时从 440 Hz 线性扫到 880 Hz；画面上把两路方波与噪声脉冲同屏绘制，肉眼可见扫频密度变化。
- 文案必须包含 `SWEEP 440 > 880 HZ / 150 MS`、`OSC1 SQUARE 50% / OSC2 SQUARE 25% / NOISE LFSR-17`、`AUDIO_CORE: DUAL_PULSE OK`，末尾打印 AUDIO READY。
- 第 54 帧结束，切 ATTRACT_TITLE，帧计数归零；音频上下文保持到游戏结束。

阶段 4　ATTRACT_TITLE（不定长，吸引模式）
- 左侧是自动寻路演算的实况回放：由确定性转向逻辑驱动一台幽灵车跑环道，画面必须是真实解算结果，不得是录像或静态图；边框标注 `AUTO PATHFINDING ATTRACT REPLAY`。
- 右侧是标题与招商信息：AXELPULSE 大字、副标题 AXIS PULSE / ORBITAL DRIFT、`5 BANDS / 24 PLATES / 10 LAPS`、`DUAL PULSE AUDIO / 5X7 HAL FONT`。
- `INSERT COIN / PRESS SPACE` 必须按 1.0 s 周期的正弦呼吸（透明度或亮度连续变化），下方打印 COIN 00 CREDIT 00。
- 列出三档难度：1 EASY / 2 NORMAL / 3 HARD；数字键可切换。
- 右下打印 `HAL STAGE 3 / ATTRACT_TITLE` 与已运行秒数 T n.nn S。
- 该阶段不推进比赛物理，但幽灵车与风场继续演算；分数、圈数、蓄能不得变化。

阶段 5　STAGE_INTRO_LOCK（180 帧 = 3.0 s）
- 由投币/空格触发。背景继续跑视差与呼吸，但物理完全锁定：油门、刹车、跃迁、蓄能、速坠、索、脉冲一律无效，车辆停在起跑格。
- 中央显示 3-2-1-GO：0–54 帧显示 3，54–108 帧显示 2，108–162 帧显示 1，162–180 帧显示 GO；第 180 帧放行并切换到 PLAYING。
- 必须同时打印剩余时间 `DEPLOY IN n.nn S` 与一条自左向右的进度条；剩余时间与进度条必须由「180 − 当前帧」直接推导，数字、进度与倒计时字三者严格自洽（例如帧 70 显示 2、剩余 1.83 s、进度约 39%）。
- 标题行打印 `STAGE_INTRO_LOCK / PHYSICS LOCKED`。
- 第 180 帧结束，切 PLAYING，解除物理锁并清空启动画布；PLAYING 之后不得再出现任何启动遮罩。

终局阶段　GAME_OVER
- 10 圈完赛、稳定性耗尽、结构性解体或探针强制结算后进入。进入时冻结物理、关闭启动画布、把 HAL.stage 置为 GAME_OVER，并显示结算面板。

════════════════════════════════════════
三、压测探针协议 window.__V2W_GAME_HARNESS__
════════════════════════════════════════
1. getStage() 必须原样返回下列字符串之一：
   "POST_RAM_CHECK" | "PALETTE_BAKING" | "ATTRACT_TITLE" | "STAGE_INTRO" | "PLAYING" | "GAME_OVER"。
   注意：屏幕上阶段 2 的标题写作 PALETTE_ASSET_BAKING，但探针枚举值必须写作 PALETTE_BAKING；屏幕阶段 5 标题写作 STAGE_INTRO_LOCK，探针枚举值必须写作 STAGE_INTRO。
2. injectScanCode(scanCode, isDown)：把一次按下/抬起写进 256 字环形缓冲，不得调用 dispatchEvent 或伪造 KeyboardEvent。位定义固定为：
   1=UP，2=DOWN，4=LEFT，8=RIGHT，16=BUTTON_A，32=BUTTON_B，64=COIN/START。
   在 ATTRACT_TITLE 中注入 64 必须立即进入 STAGE_INTRO；在 PLAYING 中按位驱动车辆；其余阶段只入队不生效。
3. step(frameCount)：以固定 1/60 s 连续调用内部 tick，返回累计 tick 数。一旦被调用，rAF 循环只允许重绘，不得再推进时钟（HAL.manual 接管）。因此同一输入序列在任何时刻调用 step 都必须得到逐位相同的结果。
4. getStateChecksum() 必须严格使用：
   ((tickCount * 31) ^ (playerX_fixed * 17) ^ (playerY_fixed * 13) ^ score) >>> 0
   其中 playerX_fixed / playerY_fixed 为内存中的 ×100 定点整数，score 取整。同一帧连续调用两次必须相等；在无输入的空跑中不得漂移。
5. getMemory() 至少返回 { bytes, tick, head, tail, buffer }，bytes 必须恒为 65536。
6. 探针不得改变渲染路径：注入按键后画面的表现必须与真人按键一致。

════════════════════════════════════════
四、竞速内核（PLAYING 阶段的强耦合系统）
════════════════════════════════════════
以下子系统不得少于 12 个，彼此必须互相读写，严禁出现只显示不参与的装饰条：
1. 非欧极坐标环道解算核心（闭合曲线采样、内外缘判定、带宽归属）。
2. 五带微气象与风切矢量场（逐带风剪、切向风与横向风合成）。
3. 分带配额与汇率包络引擎（逐带配额、逐圈重发、抽取、置换与手续费）。
4. 车辆动力学与非线性阻尼（极坐标推进、漂移滑移角、顺逆风差异）。
5. 浮屿板衰变与崩落体系统（完好/引信/虚空三态、碎片生成、重建、回收与逾期）。
6. 主动式蓄能与过载熔断引擎（三段氮气、蓄能压缩、越限截断与可见泄放）。
7. 承压应变与稳定性储备双轴耦合（承压升高挤占转向权限，稳定性被侵蚀）。
8. 结构疲劳与动态分支决策器（疲劳累积触发危机分支与轴心卫戍实体）。
9. 外部波次放行与清波回收（按帧号预排的 12 波计划、在场实体、回收计数）。
10. 整数守恒记账与逐帧事件溯源账本（五科目、缺口恒零、环形事件缓冲 ≥48 条）。
11. 同调驻留与时延判定器（低速窗口、驻留累计、跃迁余量置位）。
12. 种子化确定性初始化（同一 seed 必须复算出逐像素一致的派生指纹）。

十四阶互斥状态机（仅在 PLAYING 内运行，与 HAL 五阶段正交）：
BOOT_SEQUENCING → TITLE_LOBBY → SEEDED_INITIALIZING → GRID_LOCKED → ACTIVE_ENGAGED → ATTUNEMENT_DWELL → GALE_CROSS → WAVE_ENGAGED → DYNAMIC_BRANCHING → STRAIN_CRITICAL → QUOTA_EXHAUSTED → OVERLOAD_PENALTY → CRISIS_FAILED_ROLLBACK → RUN_SETTLED_LEDGER。
优先级（自高至低）：RUN_SETTLED_LEDGER > CRISIS_FAILED_ROLLBACK > OVERLOAD_PENALTY > STRAIN_CRITICAL > QUOTA_EXHAUSTED > GRID_LOCKED > WAVE_ENGAGED > DYNAMIC_BRANCHING > GALE_CROSS > ATTUNEMENT_DWELL > SEEDED_INITIALIZING > ACTIVE_ENGAGED。
裁决必须写成「候选集合 + 优先级表」两段数据再取最高者，禁止用 if/else 的书写顺序碰巧凑对。HUD 顶栏的状态徽标必须与裁决结果同帧一致。

仪表（至少 15 个，分布在 6 块独立 canvas 上）：
① 速度矢量仪 ② 风切矢量罗盘 ③ 五层环带整表（摩擦/风剪/配额/上限） ④ 承压应变条 ⑤ 实时损耗率监视器（GAS/STB/STR/STN 四路等距） ⑥ 稳定性储备 ⑦ 结构疲劳 ⑧ 氮气三段能量 ⑨ 蓄能压缩量（含安全线） ⑩ 分带配额沙盘 ⑪ 分带汇率包络与置换账 ⑫ 浮屿寿命环形条 ⑬ 同调充盈环 ⑭ 守恒科目表 ⑮ 收益倍率账本与连击蓄能槽。
每块 canvas 独立尺寸、独立上下文、独立绘制函数，禁止先画一张大图再裁切。任何仪表在运行中读数恒定不动，视为未实现。

十种手势（均须有代价与冷却）：
手刹漂移（滑移角越限时衰减速度并转化为竞速功）、浮空跃迁（消耗跃迁余量）、长按蓄能弹射（越限即熔断）、空间相位翻转（旋转锁定窗口内失效）、能量索抓取摆荡（脱索窗口内不可再抓）、浮屿共振同调脉冲（先完成驻留才可释放）、动量下压速坠冲击（高速俯冲非线性放大）、竞速功兑换入、牵引储备兑换出、分带配额置换。

三大反直觉地雷（必须原样实现，并由启动后不变量自检真实检测）：
1. 接触同调时延：落在锚点上不得立即重置跃迁余量；必须在 |v| < 0.05 下连续驻留 350 ms 才置位。
2. 零被动恢复：能量、护盾、动能、稳定性不随时间自然回升；停在浮屿边缘每秒扣 5% 稳定性。3 秒零输入不得出现任何正向增长。
3. 反常识风阻：顺风方向阻力被放大 40%，顺风反而更慢；逆风产生升力；离台下沉随撞击强度超线性增长，反方向弹起恢复系数固定 0.68；离台满 500 ms 后残余结构碎裂为虚空。

守恒账本：
五个整数科目——屿壳总和、牵引储备、蓄能存量、竞速功、熵损。任何手势、兑换、置换、崩落、回溯、结算都必须在同一帧内对至少两个科目做相反方向记账。恒定不变式：五科目之和恒等于 200000 千分位总额，「缺口」恒等于 0。账本逐条记录帧号、时间、事件类型、金额与注记，环形缓冲 ≥48 条，并至少在 HUD 的科目表中显示最近三条。

七、红线（任一违反即整题判负）
════════════════════════════════════════
1. 单个 .html，CSS/JS 全内联；禁止 CDN、iframe、外部图片、外部音频与任何网络请求。
2. 所有图像由 Canvas 程序化绘制，所有音效由 Web Audio 合成。
3. 不得出现 ctx.font / fillText / strokeText / measureText；不得有任何 DOM 文字被画进 canvas。
4. 不得在 window 上暴露除 AXELPULSE 与 __V2W_GAME_HARNESS__ 以外的名字。
5. 64 KiB ArrayBuffer 必须真实分配并被读写；Float32 视图必须从字节偏移 2048 开始。
6. 1280×720 下直接启动，初始画面非白非黑；连续运行 60 秒不得出现未捕获异常。
7. 五阶段帧数必须精确为 72 / 84 / 54 / 不限 / 180；探针 getStage 在边界处必须返回下一阶段的枚举值且 getStageFrame 归零。
8. 主循环固定 1/60 s；探针接管后 rAF 不得推进时钟；同一输入序列的校验和必须逐位一致。
9. 五科目之和在任意时刻恒等于 200000，缺口恒为 0；连续 60 秒与 400 次随机 API 揉搓后仍为 0。
10. 画布上不得出现未翻译汉字或由翻译失败产生的 '?'。
