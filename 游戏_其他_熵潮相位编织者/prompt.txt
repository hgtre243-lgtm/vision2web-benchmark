# 熵潮 · 相位编织者 ENTROPY TIDE / PHASE WEAVER —— 单文件可交互仿真

## 第 1 层 · 任务背景与系统定位

你需要在**一个标准自包含 .html 文件**内，实现一个名为「熵潮 · 相位编织者」的**非欧弹幕生存仿真**。全部样式与脚本必须内联，不得引用任何外部资源。

场景设定：一枚**相位核心**被投入被称为「熵潮海域」的封闭战场。海域内散布若干**引力井**——它们不是障碍物，而是**时空曲率的源**：弹幕在井附近穿行时会被弯折，并且**其瞬时速率由所在位置的局部时空度量决定**。也就是说，**同一时刻战场上不同区域的弹幕速度并不相同**，「弹速」不是全局常量，而是一个与位置相关的连续场。

核心自身**不产生任何能量**。它唯一的回充途径，是**主动贴近敌方弹幕滑行**——但贴近会以**远高于回充增速的次幂**侵蚀护盾。核心还有一个可切换的**相位极性**，它不改变核心自身的受力，而是**改写整个战场的弹速场方向**。

本关卡的验收对象**不是画面美观度**，而是一套**多子系统强耦合的动力学系统**是否被真实实现。任何试图用「固定弹幕脚本 + 状态标志位」蒙混的实现，都会在下列行为级验收中暴露。

## 第 2 层 · 核心机制与环形耦合子系统

必须实现**不少于 5 个互相制约的子系统**，且它们构成一个**闭环**：A 产生的数据制约 B，B 消耗 C，C 的阈值熔断 D，D 的结算结果决定 E，E 又反过来改写 A 的输入。至少包含：

1. **弹幕编排与发射器组**——战场上存在若干**独立发射器**，每个发射器维护自己的**臂数、旋转角速度、发射间隔、弹速基准**。发射器不是固定炮台：其参数必须**随波次推进被改写**，且必须能够被玩家**暂时过载停火**（见子系统 4）。
2. **时空度量与引力井**——引力井**缓慢公转**并各自维护质量与影响尺度。弹幕在井附近受到连续弯折；并且弹幕的**速率模长必须被重新归一到「弹速基准 × 该点局部时空度量」**。这意味着弹幕改变方向**不改变它的表观速度**，但穿过度量场时速度会连续变化。禁止把井写成纯视觉装饰。
3. **擦弹熵能**——核心周围存在一个**擦弹判定环**。任何落入环内、且未进入命中判定的敌方弹幕，都按**贴近度**持续回充熵能；同时按**同一个贴近度**持续侵蚀护盾。两条曲线必须是**不同次幂**的（见陷阱 T3），使得贴近度越过某个临界后**净收益转负**。
4. **相位极性场与反演熔断**——核心的相位极性（吸附／排斥）会**整体反转战场弹速场对弹幕的作用方向**。瞬切极性**不是过滤、不是清除**，而是把**每一颗仍在场的敌方弹幕的速度沿「战场中心 → 弹幕」的径向做镜像**，从而**整体反转其角动量**。瞬切与反演齐射都受**熵能门槛门控**：熵能不足时操作必须被**拒绝**（而非降级生效）并在日志留痕。
5. **潮汐波次调度**——波次不是固定脚本。调度器必须**根据当前战场压力**（在场敌方弹幕的密度）**改写发射器的臂数与发射间隔**，并在波次之间插入**间歇**：间歇期内发射器停火、场上残余弹幕被清除、护盾小幅回充。
6. **多维因果计费账本**——逐帧累积一条**时序样本序列**，记录每一帧的核心坐标与速率、熵值、熵能、护盾、擦弹贴近度、敌方／己方弹幕数、局部时空度量、以及该帧内的擦弹获得量、熵值衰减流失量、反演转化数、生成弹幕数与事件标记。结算时的三项指标**必须由该序列在结算时刻回溯聚合得出**。

**环形闭合要求**：波次调度改写发射器参数 → 发射器生成弹幕 → 弹幕在引力井附近被弯折、其速率被局部时空度量改写 → 核心必须贴近弹幕才能回充熵能，而贴近消耗护盾 → 护盾跌破临界触发失败态、熵能跌破门槛则相位操作被拒绝 → 相位瞬切反转弹速场并整体改写既有弹幕的角动量、反演把敌方弹幕转为己方并回充护盾 → 己方弹幕过载敌方发射器、反过来压制生成速率 → 账本汇总上述全部。**任何一环被写成常量或绕过，判定该系统未实现。**

## 第 3 层 · 显式有限状态机

必须实现**不少于 8 个互斥状态**（本关卡要求 **12 个**），且**严禁用若干全局布尔变量的组合来隐式决定行为**。状态必须由一个**单一枚举字段**承载，每一次进入状态都要执行明确的进入动作。优先级**自上而下**，高位状态压制低位状态：

| 状态名 | 前置守卫 Guard | 触发源 Trigger | 转移目标 Next State | 系统副作用 Action |
|---|---|---|---|---|
| `RUN_SETTLE` 跃迁结算 | 任一失败终止或主动结算 | 结算触发 | 重新跃迁 | 冻结物理；由时序序列回溯聚合三项指标并渲染结算面板 |
| `CORE_BREACH` 相位核心击穿 | 护盾被扣至零以下 | 护盾越零当帧 | `RUN_SETTLE` | 核心失效；进入不可逆失败倒计时；日志留痕被弹次数与当时熵值 |
| `ENTROPY_FLOOD` 熵潮泛滥 | 熵值越过泛滥阈 | 熵值越阈 | `SHIELD_CRITICAL` / `NEUTRAL_PATROL` | 全局告警；熵能衰减率被熵值放大；收益倍率表中的熵值压制项显著下滑 |
| `SHIELD_CRITICAL` 护盾临界 | 护盾低于临界余量且未越零 | 护盾跌破临界 | `ENTROPY_FLOOD` / `CORE_BREACH` | 告警色切换；擦弹判定环光学降级；日志留痕剩余护盾 |
| `INVERSION_BURST` 反演齐射 | 熵能越过反演门槛且不在冷却 | 反演键按下 | `SATURATION_DRIFT` / `NEUTRAL_PATROL` | 将作用半径内的敌方弹幕**整批转为己方弹幕**并回充护盾；扣除熵能；半径内无敌方弹幕时**仍然扣除熵能**并记为未命中 |
| `POLAR_FLIP` 相位瞬切 | 熵能越过瞬切代价且不在冷却 | 瞬切键按下 | `NEUTRAL_PATROL` | 极性取反；对**全部**在场敌方弹幕执行径向速度镜像；扣除熵能；冷却期内重复输入必须被拒绝并留痕 |
| `DILATION_ZONE` 时空膨胀域 | 核心所在位置的局部时空度量越过膨胀阈 | 进入高曲率区 | `GRAZE_CHANNEL` / `NEUTRAL_PATROL` | 该区域内弹幕速率被整体抬升；曲率仪与雷达同步高亮；引擎不得对该区域做任何特殊脚本处理 |
| `GRAZE_CHANNEL` 擦弹通道 | 擦弹贴近度越过通道阈且未进入命中 | 贴近度越阈 | `SATURATION_DRIFT` / `NEUTRAL_PATROL` | 判定环光学点亮；收益倍率表的擦弹项实时抬升；护盾按更高次幂持续流失 |
| `SATURATION_DRIFT` 饱和漂移 | 在场敌方弹幕数越过饱和阈 | 密度越阈 | `NEUTRAL_PATROL` | 密度环告警；发射器进入过载间歇；判定环收缩以降低误命中 |
| `FOCUS_CRAWL` 聚焦滑行 | 聚焦键被按住 | 聚焦键按下 | `NEUTRAL_PATROL` | 推进力与限速被压低；擦弹判定半径被放大；**熵增速率不因此降低** |
| `INTERMISSION` 波次间歇 | 上一波次时长走完 | 波次计时到顶 | `NEUTRAL_PATROL` | 发射器停火；残余弹幕全部清除；护盾小幅回充；波次序号自增并改写发射器参数 |
| `NEUTRAL_PATROL` 相位中立巡航 | 以上全部不成立 | 默认态 | 任意高位状态 | 无附加副作用；作为状态机的稳定基态 |

**状态互斥性要求**：任一帧内 `state` 字段只能取上表中的一个值；状态转移必须在事件日志中留痕（形如 `STATE → 状态名`），日志**只增不减**；主视口的状态条必须与该单一枚举字段**逐帧一致**。

## 第 4 层 · 行为因果回路与反直觉陷阱

### 4.1 复合手势（不少于 5 组）

1. **长按聚焦滑行**——按住聚焦键：推进力与限速被压低，但**擦弹判定半径显著放大**。用于在密集弹幕中穿针引线。**熵增速率不因聚焦而降低**，因此「龟缩保命」是净亏策略。
2. **贴弹滑行取能**——沿弹幕的**切向**保持极小间距滑行：越贴近，熵能回充越快，但护盾流失以**更高次幂**放大。存在一个临界贴近度，越过之后**净收益转负**。
3. **相位瞬切**——瞬切极性：并非清除弹幕，而是把**每一颗在场敌方弹幕的速度沿战场径向镜像**。即将离场的弹幕会**掉头折返**，贴脸飞来的弹幕会**加速远离**。有冷却，冷却期内按下必须被拒绝。
4. **反演齐射**——熵能越过门槛后释放：把半径内的敌方弹幕**整批反演为己方弹幕**，己方弹幕会自动追击最近的发射器并将其**过载停火**，同时回充护盾。
5. **相位冲刺**——在极短窗口内**双击同一方向**：消耗熵能获得一次爆发速度与无敌帧，冲刺期间**速度不受巡航限速约束**；代价是**冲刺期间熵增速率翻倍**。

### 4.2 反直觉阻尼规则（不少于 3 条，均为强制的验收点）

- **陷阱 T1 · 静止惩罚**——**熵值在静止时加速增长**。核心的归一化速率越低，熵增越快；熵值越高，熵能衰减越快。因此「原地不动避弹」在长时间尺度上**必然先耗尽熵能**，从而丧失全部相位操作能力。无操作状态下熵能**绝不自发恢复**。
- **陷阱 T2 · 瞬切反转角动量**——相位瞬切**不做过滤、不做清除**。它的语义是**径向速度镜像**：沿「战场中心 → 弹幕」方向的速度分量保持不变，与之垂直的分量整体取反。其可观测后果是：**本来正在飞离战场的弹幕会掉头飞回来**，而**本来正在逼近核心的弹幕会改为远离**。因此「用瞬切清屏」是**错误直觉**：瞬切之后弹幕总数不变，只是全部改了航向。
- **陷阱 T3 · 极限贴弹是陷阱**——熵能回充随贴近度以**低次幂**增长，护盾流失随贴近度以**高次幂**增长。两条曲线必然相交：在低贴近度区间净收益为正，越过临界点后**净收益转负**。验收时必须在两个不同贴近度上分别测量「单位时间熵能获得」与「单位时间护盾流失」的比值，高贴近度的比值必须**显著高于**低贴近度（不低于 2.5 倍）。「越贴近越赚」是**错误直觉**。
- **陷阱 T4 · 局部时空度量**——弹幕速度**由所在位置的时空度量决定**，不是全局常量。同一时刻，靠近引力井的弹幕明显快于远离引力井的弹幕。界面上必须同时给出**核心所在点的局部度量读数**与**由该度量换算出的弹速增益百分比**。禁止把弹速写成常数，禁止在引擎里对「高曲率区」做任何特殊分支——**曲率必须是场，不是区域标记**。

### 4.3 两阶段确认

- **相位操作两阶段**：第一阶段「熵能储备越过门槛」，第二阶段「操作键按下」才生效。任一阶段缺失（熵能不足／冷却未走完），第二阶段的输入必须被**吞掉**（而非降级生效），并写入一条拒绝日志。
- **冲刺两阶段**：第一阶段「同一方向键在极短窗口内被按下两次」，第二阶段「冲刺位移生效」。窗口外的第二次按下必须**降级为普通方向输入**，不得触发冲刺。

### 4.4 失败重试闭环

护盾越零（相位核心击穿）、波次全部走完（跃迁完成）、主动结算三条路径都必须进入结算态。结算态必须显示**三个指标 + 结算原因 + 本次参与聚合的帧样本数**，并提供**重新跃迁**入口；重新跃迁后世界重新生成但**随机种子保持不变**（同一台机器上两次重新跃迁的引力井布局与发射器布阵必须**逐位一致**），账本清零。

### 4.5 结算口径（写死数值直接判零）

结算面板上的三项指标必须**全部由一个逐帧累积的时序样本序列在结算时刻回溯聚合**得出：

- **擦弹转化率**：回溯全时段，计算**擦弹获得的熵能总量**占**（擦弹获得总量 + 熵值衰减流失总量）**的比例。
- **熵值时间均值**：回溯全时段，计算熵值对时间的**加权积分均值**（逐帧熵值之和 ÷ 帧样本数）。
- **反演收益率**：回溯全时段，计算**被反演转化的弹幕数**占**累计生成弹幕数**的比例。

**硬性判定**：若实现中这三项由任意常量、任意与帧序列无关的计数器、或任意「看起来合理」的公式直接产出，本题判零。结算面板必须同时标注本次参与聚合的**逐帧样本条数**，该条数必须等于物理帧数组的实际长度；且当玩家**全程未发生任何擦弹与反演**时，第 1、3 项必须精确为零。

### 4.6 能量守恒约束

**核心在静止状态与无操作状态下，熵能与护盾绝不自然恢复**。静止时不得出现任何自发速度增长；无输入时不得出现相位瞬切、反演齐射、相位冲刺、擦弹、被弹等计数的自发增长。

## 第 5 层 · 技术边界与绝对禁止项

**允许**：单个自包含 .html 文件；内联样式与内联脚本；程序化绘制的矢量图形（含渐变、阴影、粒子）。

**绝对禁止**：

1. 禁止任何外部网络资源——不得出现外部样式表、外部脚本、外部字体、外部图片、嵌入式子文档框架。
2. 禁止位图资源——所有视觉元素必须由代码绘制。
3. 禁止在实现中使用任何**具名缓动函数**或**现成插值公式**；一切运动必须由**逐帧力／加速度积分**产生。
4. 禁止硬编码像素常数或逐点脚本化的弹幕轨迹来伪造物理——弹幕航向、弹速、弯折、判定距离必须由状态量实时求解。
5. 禁止用弹窗类阻塞接口做交互反馈，禁止向文档流写入内容。
6. 禁止把状态判定写成若干全局布尔量的组合；必须是单一枚举 + 显式转移表。
7. 禁止在静止状态恢复熵能或护盾。

**渲染架构硬约束**：

- 主战场、仪表阵列、弹幕拓扑雷达**必须是三块相互独立的渲染画布**，各自拥有独立的重绘节拍与独立的绘制逻辑，但**共享同一份内存物理态**。禁止用单画布分区绘制冒充多画布。
- 主战场必须把**局部时空度量以可见的几何形变呈现**——例如一张会出现连续弯曲的参考网格；弯曲程度必须随引力井的位置实时变化，而非静态贴图。
- 主视口必须在 1440×900 视口下无横向与纵向溢出；在 1280 / 1024 / 900 / 768 / 414 / 375 宽度下均不得出现溢出，且主画布必须保持可见且尺寸充足。
- 分辨率缩放必须自适应设备像素比，画布不得出现模糊或拉伸。

**仪表硬约束**：必须提供**不少于 5 组独立仪表**，至少包含：相位罗盘（指示当前极性与弹速场方向）、熵潮示波条（对熵值做**时序**波形，非瞬时数值）、弹幕密度环（指示在场敌方弹幕数与己方弹幕数）、时空曲率仪（指示核心所在点的局部度量并给出该点的曲率形变缩略图）、熵能与护盾双条（并标注反演门槛位置）。仪表读数必须**随物理态实时刷新**，禁止使用占位数值。

**运行质量硬约束**：页面启动后**控制台不得出现任何未捕获异常、任何资源加载失败、任何脚本错误**；持续运行不得崩溃；在场上同时存在数百颗弹幕的饱和状态下，渲染循环必须稳定在 40 帧/秒以上。

**交付物**：一个 .html 文件，外加一组连续状态的参考截图（1440×900）。题面描述与实现必须完全自洽——任何一处「题面说了但实现没做」或「实现做了但题面没说」都视为不通过。
