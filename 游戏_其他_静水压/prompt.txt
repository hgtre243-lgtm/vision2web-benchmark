静水压 HYDROSTAT · 压载深潜（复古 HAL 加难卷 v3）

做一个"用波义耳气囊与压载配平解算垂向动力学、在十四阶互斥状态机、五个整数守恒科目与五带配额之间反复取舍、并抵挡十波深渊涌升"的网页深海作业游戏。单文件、整屏、深海仪表台风格，镜头固定侧视剖面。images/ 下的 8 张 1536×864 截图是同一局在同一会话内的 8 个互斥状态快照，**图是唯一权威**：图上能直接读到的读数、文案、配色、几何位置、条长与数值一律照搬；图上读不到的才由实现方自行选定，且必须与下文全部响应关系自洽。

一、世界与基础操纵面
海域是一张 13 列 × 13 行的竖直剖面：第 0 行水面（母船补给区停在中偏左，一条脐带垂下连住潜航体），第 12 行海床。五层密度剖面自上而下为光合层、温跃层、密度跃层、暗层、压碎层，每层各有独立的相对密度、透光率与耗氧倍率；层界在画面上表现为横向虚纹，其中密度跃层那一道最锐。板上 7 处可站立浮屿＝5 段沉船残骸舱段＋2 座热液喷口基座；喷口正中一条窄带才是"精准同调核心区"，站在喷口格但偏出窄带即为陷阱格——既不产同调，又按边缘规则扣稳定性。左下与右下两处深渊出怪舱口。五类深渊生物：磷虾群、巨口鳗、铁甲蟹（甲壳只被越过速度门的冲击波或同调脉冲击穿）、压力波（穿水而过、不可拦截的行波）、深渊王（第 10 波）。共 10 波，数量、混编与血速倍率逐波抬升。
潜航体只有一条垂向自由轴——**没有跳跃，也没有二段跳**。A/D 或左右键给横向推力；W/S 或上下键注/排压载（**慢配平**：只能按固定速率逼近目标，不可瞬变）；J/K 气囊注气与排气（**快操纵**）；1/2/3 切换难度；P 暂停；R 重开；Esc 回母船。压载改变自重、气囊改变排水体积，而静水压又反过来压缩气囊——三者物理地位不同，垂向必须提前预判，任何一步都刹不住车。

二、复古街机硬件抽象层（HAL）与零全局状态（强制）
2.1 整个游戏只允许一个 IIFE；除唯一引擎实例 `window.HYDRO` 与测试握手 `window.__V2W_GAME_HARNESS__` 外，不得向 window 挂任何游戏变量，也不得出现散落的顶层 `var/let` 游戏逻辑全局。所有运行期状态收敛进引擎内部的单一状态对象。
2.2 引擎启动时分配**唯一一块 65536 字节的 `ArrayBuffer`**，核心状态全部落在这块内存上，至少建立 `Int32Array`、`Float32Array`（字节偏移 2048）、`Uint8Array` 三个视图。玩家坐标用 ×100 定点整数存放，速度/应变/同调/压载/气囊/时间用 Float32 槽位；对象上的 `x/y/vx/vy/score/life/o2/wave/strain/attune/...` 必须是绑定到该内存的访问器（getter/setter 直读直写视图），不得另存一份影子副本。
2.3 固定槽位图（Int32 视图，下标以字为单位）：0 TICK、1 STAGE、2 SCORE、3 PX、4 PY、5 LIFE、6 O2、7 WAVE、8 GAP、9 LAUNCH、10 RING_HEAD、11 RING_TAIL、32 起为按键环形缓冲 KEYQ。Float32 视图：0 PX、1 PY、2 VX、3 VY、4 CHARGE、5 STRAIN、6 ATTUNE、7 BALLAST、8 BLADDER、9 T、10 GAS。
2.4 按键环形缓冲固定 256 字。每字打包 `((scanCode & 127) << 1) | (isDown ? 1 : 0)`；head/tail 存在上述内存槽位，写满时丢最旧一条。物理按键与测试注入都必须只经这一条环形缓冲进入操纵解算，禁止绕开它直接改 keystate。
2.5 引擎在任意时刻只推进一个固定状态机；渲染、音频、输入、计分共享同一帧号，禁止各自维护独立时钟。

三、5×7 位图字库（画布文本唯一合法路径）
3.1 内嵌 5×7 十六进制点阵字库，覆盖 A–Z、0–9 与常用符号（空格 . , : ; / % + - = > < ( ) [ ] ! ? ' # * | \ ^ _ @ & " $ ~）。每个字符 7 行、每行 2 个十六进制位（低 5 位有效）。
3.2 文本必须先逐像素光栅化到离屏 canvas，再以 `imageSmoothingEnabled=false` 的最近邻 `drawImage` 贴回目标画布；允许按整数倍缩放与按色缓存，但不得拉伸插值。
3.3 **启动自检与全部画布 HUD/仪表/横幅不得出现任何 `ctx.font` 赋值或 `ctx.fillText` 调用**；违者按红线判零。DOM 面板（顶栏、结算 HTML 层）可以使用系统字体，但画布内一个像素的中文/矢量字都不许有。
3.4 字库渲染必须支持左对齐/居中/右对齐与颜色参数；同一字符串同色同倍率应可缓存复用。

四、五阶段确定性启动管线（加载即执行，不得跳过、不得并行）
所有阶段推进只读内部 60 Hz 帧计数，不读墙钟；渲染帧率变化不得改变任何阶段时长。
STAGE 0 `POST_RAM_CHECK`（额定 72 帧＝1.2 s）：全屏黑底启动画布，绿/青终端行自上而下逐行滚出，逐行带 `>` 前缀；必须逐字出现且只出现一次以下三行：
`VRAM ALLOC: 0x8000 OK`
`AUDIO_CORE: DUAL_PULSE OK`
`PRNG SEED BOUND: OK`
同时至少包含：BIOS 版本行、`CPU: 68000 COMPAT / 60 HZ FIXED TICK`、64K RAM 校验 PASS、16×RGB444 调色板 RAM PASS、LFSR-17 噪声 PASS、SHEET A/B 挂载、JAMMA 7 位扫描环 READY、确定性时钟 LOCK、ATTRACT PATHFINDER ARMED、BOOT COMPLETE。右上角常驻 `STAGE 0 / FRAME nn / 72`（FRAME 为该阶段已过帧数，只有一个计数器，不得再放第二个语义不明的 TICK 读数）；底部给出该帧从内存视图实读的十六进制转储。任一行不得写死进度百分比，帧读数必须来自当前帧。
STAGE 1 `PALETTE_ASSET_BAKING`（额定 84 帧＝1.4 s）：**零外部图像 I/O**，全部像素在内存中生成。必须同屏烘焙两张图集：Sheet A 为 4-bit 索引图集，含角色 4 帧、敌人与地块共 16 个图块；Sheet B 为 16 色 palette swap 图集，带扫描线扫过。底部像素格进度条从 0 走到 100%，大字显示实时 `BAKING nn%`；页脚给出 `64K ARRAYBUFFER / 256-WORD SCAN RING / 0 EXTERNAL FETCH` 与 SHEET A / SHEET B / PALETTE 三项逐项完成状态。
STAGE 2 `CHIP_AUDIO_WARMUP`（额定 54 帧＝0.9 s）：Web Audio 必须真实创建 **2 个 pulse/square `OscillatorNode` + 1 个白噪声 `AudioBufferSourceNode`**（噪声由 LFSR 生成，不得用现成噪声文件）。双振荡器做 150 ms 的 440→880 Hz 线性扫频，页面必须画出两路方波波形、扫频标注 `SWEEP 440 > 880 HZ / 150 MS`、`OSC1 SQUARE 50% / OSC2 SQUARE 25% / NOISE LFSR-17`、`AUDIO_CORE: DUAL_PULSE OK` 与就绪标记。AudioContext 被浏览器挂起时允许显示待唤醒，但不得报未捕获异常。
STAGE 3 `ATTRACT_TITLE`（无限期，直到投币/开始）：左侧 592×592 演示窗把主视窗画布实时搬入，展示**内置自动寻路 attract 回放状态机**——幽灵潜航体沿固定航点序列自动移动、周期性自动放脉冲，不得是静止截图；右侧大号 `HYDROSTAT` 标题、`BALLAST DESCENT` 副题、`5 STRATA / 7 WRECKS / 10 WAVES`、`DUAL PULSE AUDIO / 5X7 HAL FONT`。`INSERT COIN / PRESS SPACE` 必须按**正弦呼吸闪烁，周期严格 1.0 s**；旁列 `COIN 00 CREDIT 00`、三档难度 `1 SHALLOW 2 NORMAL 3 ABYSS`、`HAL STAGE 3 / ATTRACT_TITLE` 与运行秒数。按 1/2/3 切难度，按 Enter/Space 或投币（扫描码 64）进入 STAGE 4。
STAGE 4 `STAGE_INTRO_LOCK`（额定 180 帧＝3.0 s）：大字倒计时 3→2→1→GO，各占 54 帧；`DEPLOY IN x.xx S` 必须等于**本阶段剩余帧数 ÷ 60**，因此四个大字对应的剩余时间区间固定为：`3`→3.00–2.10 s、`2`→2.10–1.20 s、`1`→1.20–0.30 s、`GO`→0.30–0.00 s，任何一帧都不得越区显示。背景视差、洋流与角色呼吸动画必须继续运行，但物理积分、位移、波次与计分全部锁定。画面给出 `STAGE_INTRO_LOCK / PHYSICS LOCKED`、`DEPLOY IN x.xx S` 与 420×10 进度条。**恰好 180 帧后**切入 `PLAYING`，不得提前、不得延后、不得按键跳过。

五、测试握手协议（`window.__V2W_GAME_HARNESS__`）
必须原样暴露，不得改名、不得附加前置条件：
- `getStage()`：只返回六个字符串之一——`"POST_RAM_CHECK"`、`"PALETTE_BAKING"`、`"ATTRACT_TITLE"`、`"STAGE_INTRO"`、`"PLAYING"`、`"GAME_OVER"`。STAGE 1 与 STAGE 2 都归并为 `"PALETTE_BAKING"`；结算后为 `"GAME_OVER"`。
- `injectScanCode(scanCode, isDown)`：JAMMA 扫描码 1=UP、2=DOWN、4=LEFT、8=RIGHT、16=BUTTON_A、32=BUTTON_B、64=COIN/START。只准写入 2.4 的环形缓冲，**禁止伪造 DOM KeyboardEvent、禁止直接改 keystate**；非法码返回 false。
- `step(frameCount)`：以内部 60 Hz 固定步长推进指定帧数，期间锁死 rAF 墙钟推进，避免双重计时；结束后重绘一次。`step(0)` 不得改变任何状态。
- `getStateChecksum()`：严格返回 `((tickCount * 31) ^ (playerX * 17) ^ (playerY * 13) ^ score) >>> 0`。状态未变化或冻结时连续读取必须完全相等，不得因渲染次数、缓存或墙钟而漂移。
六个阶段字符串之外不得返回任何别名；六个阶段必须能从页面加载起按固定顺序自然到达。

六、十四阶互斥有限状态机（PLAYING 之后的局内裁决）
HAL 的五阶段是最外层管线；进入 PLAYING 后由下列十四阶状态机接管，同一帧多条件并立时按**固定优先级**裁决，前者胜出，任何两态不得同时为真；禁止用一堆全局布尔量组合冒充状态：
BOOT_SEQUENCING ＞ RUN_SETTLED_LEDGER ＞ CRISIS_FAILED_ROLLBACK ＞ TITLE_LOBBY（自锁）＞ OVERLOAD_PENALTY ＞ STRAIN_CRITICAL ＞ QUOTA_EXHAUSTED ＞ GRID_LOCKED ＞ DYNAMIC_BRANCHING ＞ WAVE_ENGAGED ＞ GALE_CROSS ＞ ATTUNEMENT_DWELL ＞ SEEDED_INITIALIZING ＞ ACTIVE_ENGAGED
其中 BOOT_SEQUENCING 绑定 STAGE 0–2，TITLE_LOBBY 绑定 STAGE 3，STAGE 4 期间状态冻结、进入 PLAYING 后从 SEEDED_INITIALIZING 或 ACTIVE_ENGAGED 起算。

七、环形耦合子系统（≥10，环环相扣，任何一个都不得独立成立）
1 **非欧微气象与动力学矢量核心**：洋流不是常数，而是多层内波模态叠加出的矢量场，振幅、波数、频率与相位随层带变化；密度跃层处速度剪切使跃层上下流向反号。潜航体被所在层洋流平流带走，推进器有效出力随相对流向折减——顺流时水阻被非线性放大，迎流时迎角反而产生向上的升力矢量，横向机动必须借层间流向差"摆渡"。
2 **多实体物理衰变与反作用**：每段浮屿有独立耐久、下沉位移与回弹速度；下沉量对冲击速度是饱和型非线性（速度越大越接近上限，永不超过）。潜航体离台的瞬间，那一段以小于 1 的固定回弹系数反向弹起，再经过固定引信时间碎裂为不可站立的虚空，并波及邻格。全部逐帧积分，禁止"打一下掉一格血"。
3 **主动式能量循环与过载熔断**：高压气、稳定性储备与动能**绝对禁止被动恢复**。高压气只有两个来源：喷口核心区驻留、或带足够切向速度的能量索摆荡释放；氧气只在母船补给区回充；稳定性只在核心区增长，停在浮屿边缘则按每秒固定比例流失；结构疲劳只在水面减压舱可修复。气囊**容积**越过结构上限即强制排气、扣分、进硬直并累计熔断次数。
4 **多实体空间拓扑与三层判定**：每段浮屿几何上分三层——正中核心受击点、两侧擦弹边缘、下方动量吸收域。三层判定互不相同：只有核心带计同调；边缘按秒扣稳定性；动量吸收域决定速坠冲击的传播半径与衰减。喷口格偏出窄带即陷阱格。
5 **逐帧事件溯源与结算审计**：每件有意义的事以（帧号、时刻、事件类型、带符号数额、人类可读说明）五元组记入账本，只增不删，界面滚动显示最近若干条。结算面板的每个数字都必须由这本账回溯聚合，写死数值直接判零。连续击杀累积连击段数与收益倍率，长时间无新事件即整段清零。
6 **承压应变**：应变随深度、所在层密度与速度平方抬升；只有最上一层能泄压；越过阈值即挤占横向权限并按秒抽脐带；熔断与空化都会额外抬高应变。应变峰值进结算。
7 **五带配额沙盘**：五层各有一份只减不增的配额，当前所在层按时间与速度平方燃烧；配额耗尽不是"没油"而是权限被削（横向削减、应变抬升）。打捞物回收只回补**本带**配额。
8 **层间剪切穿越**：由同一帧上下两层的流向差加上本层流向合成切应力读数，越阈即进入固定时长的穿越锁；锁定期内横向与垂向手感同时变钝，多用手势失效。
9 **出闸锁定与空化余量**：开局有一小段锁定窗口，任何局内手势无效；空化跃迁消耗本带配额与一格余量，余量耗尽须重新同调补充。
10 **五科目整数守恒账本**：屿壳总和 / 牵引储备 / 蓄能存量 / 打捞功 / 熵损，全部以千分之一为单位整数记账。任何事件只能做**科目间等额划转**，不得凭空增减；任何时刻五科目之和恒等于总额，缺口恒为 0（详见第十节）。
环形闭环（必须真闭环）：洋流矢量 → 横向与垂向姿态 → 能否停在喷口核心带 → 同调充盈 → 高压气与稳定性 → 蓄能弹射与同调脉冲 → 能否清掉压到水面的实体 → 脐带余量 → 是否触发危机分支 → 是否被迫熔断 → 熔断与剪切锁期间舱段被啃碎 → 可站立面变少 → 同调点位变少 → 回到第一步。

九、十种复合手势（全部真实可玩、各有代价，禁用状态必须给出可见理由）
1 Shift 动量下压速坠：额外下向加速度并抽走气囊容积，触底按速度生成冲击波，越速度门才击穿铁甲蟹甲壳。
2 L 非线性张力蓄能弹射：长按蓄能、松开发射；冲量对蓄能量超线性，蓄能期间持续抽气，越满越需要留上浮余量。
3 U 空间相位瞬时翻转：固定高压气代价，使浮力极性瞬时反置，并让主视窗进入视差倾角扰动窗口；稳定性不足或气不足时失效。
4 Space 能量索抓取 / 摆荡释放：抓取半径内锁定锚点，按带阻尼的单摆方程摆动；松手时按切向速度加权回补高压气，切向速度不足则无回补、离差过大同样无回补。
5 Enter 浮屿共振同调脉冲：核心区驻留满后才可释放，半径与伤害随充盈度缩放；释放即清空同调并让喷口进入冷却，**禁止连续点按刷取**。
6 X 侧倾漂移制动：把横向动能抽成打捞功，代价是承压应变上升与稳定性下降；横向速度过低时空放，剪切锁定期内被剪流抵消。
7 C 空化跃迁：吸走本带配额与一格空化余量，在气囊外缘撕出空化腔并给一次上冲；高应变、能量索咬合中、余量耗尽或本带配额不足时失效。
8 G 打捞功兑换入：把打捞功并回屿壳科目，手续费沉入熵损；余额不足时未成立。
9 Y 牵引储备兑换出：高压气按**本带实时汇率**折算成打捞功，差额与手续费沉入熵损；汇率越低换得越少。
10 B 分带配额置换：把余量最大的一带配额挪到当前带，折损部分沉入熵损；无可置换余量时未成立。
压载、气囊、横向推进、暂停/重开/返回属基础操纵面，不计入以上十种。扫描码 16 必须落到同调脉冲一类的 BUTTON_A 动作，扫描码 32 落到 BUTTON_B 动作，64 只用于投币/开始。

十、五科目整数守恒账本
屿壳总和 / 牵引储备 / 蓄能存量 / 打捞功 / 熵损，全部以千分之一为单位整数记账。任何事件只能做科目间**等额划转**，不得凭空增减，不得用浮点余额四舍五入制造漂移；任何时刻五科目之和恒等于总额，缺口恒为 0。注气、排气、气囊充放、打捞回收、舱段碎裂、熔断泄放、两种兑换、配额置换与结算扣分，全部必须走这套划转。逐帧采样：缺口一旦非零即判不变量被破坏。

十一、三颗反直觉地雷（照常识惯性实现必然失败）
1 **接触同调时延**：触地**不等于**同调。落点必须先把速度压到近零并连续保持满一段以百毫秒计的窗口，同调才开始推进；触地瞬间"落地即给"是错的，窗口内任何一次速度越界都会把进度打回。**验收探针**：触地后 200 ms 若已可蓄能或已给出正向响应，即判该条失败；松开压载后的重新蓄能同样受这条时延约束。
2 **零被动恢复与静止消耗**：高压气、稳定性储备与动能**没有任何随时间自然回复的路径**；站在浮屿边缘还要按每秒固定比例持续流失稳定性。**验收探针**：连续 3 s 零输入，五项资源中不得有任何一项出现正增长；在边缘静止时稳定性必须单调下降。
3 **反常识风阻与下沉反冲**：顺流时水阻被非线性放大（倍数见仪表组罗盘标签），迎流时迎角产生**向上的升力矢量**——顶着洋流上浮反而更省。浮屿下沉对冲击速度是饱和型：轻撞几乎不动，重撞迅速逼近上限但永不超过；离台瞬间以小于 1 的固定回弹系数反向弹起，再经固定引信时间碎裂。**验收探针**：同一帧内顺流与迎流两种姿态的垂向加速度必须符号相反；引信计时到期的那一帧起该格必须不可站立。

十三、红线（任一违反，本题直接判零）
- 交付单个 .html 文件，CSS 与 JS 全部内联，双击离线可运行；不得出现任何外部脚本、样式表、字体、图片、音频或网络资源。所有图像由 Canvas 程序化生成，所有音效由 Web Audio API 纯代码合成。
- 不得使用 iframe、srcdoc、Base64 贴图、第三方游戏框架或物理引擎。
- 不得出现散落的顶层游戏逻辑全局变量；核心坐标/速度/生命/按键环必须真的位于同一块 ArrayBuffer 的视图上，验收时以 `getMemory()` 的字节数与实际读写为准。
- 启动画布与全部 HUD 的画布文本必须走 5×7 位图字库；源码中不得残留任何 `ctx.font =` 或 `ctx.fillText(`（DOM 层除外）。
- 五阶段帧数与顺序固定，全部由内部 60 Hz 帧计数推进；不得用 setTimeout、Date.now、performance.now 或 rAF 次数替代阶段计时。
- 物理必须由逐帧速度与加速度积分产生、固定步长推进；浮力、压载、气囊容积、洋流、下沉与回弹一律按步长累加。不得用现成的具名缓动函数替代物理解算。
- 至少 6 块物理独立局内画布节点＋1 块启动画布，不得在全屏单画布内完成全部渲染。
- 所有随机量必须由固定种子驱动的确定性伪随机数发生器产生，同种子同输入逐帧可复现；禁止系统随机源。
- 禁止弹窗类阻塞接口与向文档流写入内容；不得出现占位文本、空壳面板或与真实数据不符的读数。
- 页面启动与持续运行期间，控制台不得出现任何未捕获异常、脚本错误或资源加载失败。

十五、验收
基准版式 1536×864；实测覆盖 1024、1152、1280、1366、1440、1600、1920、2560 八档宽度，均不得出现横向或纵向溢出，主视窗、状态徽标与全部仪表在这些宽度下都必须可见。基础可运行性四项缺一不可：文档语法可解析且无未闭合标签；在 1280×720 下成功启动；初始画面实际绘制出可检测的非白、非纯黑内容且全部画布都有非零墨量；从加载到交互的全生命周期内控制台无未捕获异常。固定步长不得低于 60 Hz 且不随渲染帧率变化；软件光栅化下持续运行 60 s 帧率不得持续劣化（末段窗口均值不低于首段窗口均值的 85%），长时运行不得崩溃，首帧不得白屏或黑屏。
新增硬断言：① 五阶段必须按 72/84/54/∞/180 帧的固定预算推进并在正确帧切换，任一段不得跳过；② `getStage()` 只出现六个合法字符串，顺序为 POST_RAM_CHECK → PALETTE_BAKING（含 STAGE 1–2）→ ATTRACT_TITLE → STAGE_INTRO → PLAYING → GAME_OVER；③ 投币后注入扫描码 64 必须只在 ATTRACT_TITLE 生效并进入 STAGE_INTRO，180 帧后自然变 PLAYING；④ `step(0)` 前后 `getStateChecksum()` 完全相等，`step(n)` 后必须变化，冻结期间连续读取不得漂移；⑤ `getMemory().bytes` 必须为 65536，按键环形缓冲 head 必须随注入推进；⑥ 全部画布文本由位图字库绘制，源码不存在 `ctx.font` / `ctx.fillText`；⑦ 三颗地雷的验收探针必须全部通过；⑧ 五科目账本在任意随机操作序列下缺口恒为 0、总和恒等于总额；⑨ 八张参考图两两在主视窗区域的像素差异必须显著高于同场景噪声底。
