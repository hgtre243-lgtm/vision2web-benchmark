## 第 1 层 · 任务背景与系统定位
交付一个**单文件、自包含、零外部依赖**的浏览器端三维地理分析沙盘 `index.html`，主题为「澜川流域 Ⅲ 级支流」的 DEM 数字高程与流域水文推演台。设计风格：深色作业台（背景自上而下由墨黑渐变到深青灰），所有面板为半透明玻璃质感卡片，数值一律使用等宽数位（tabular-nums）对齐，主色为青蓝（分析）与橙金（待确认），警示色仅用于拒绝与熔断。画布必须铺满视口，面板浮于其上。

本任务的目标不是"画一座山"，而是让六个子系统在同一份高程场上环形咬合：任何一次交互都必须以真实重算的数值改变画面与读数，而不是改变一句文案。

## 第 2 层 · 核心机制与环形耦合子系统
必须实现以下 **6 个**子系统，且它们互为输入输出，构成闭环：
- **S1 程序化高程场**：由固定种子 `20260925` 的确定性哈希与分形噪声生成 72 × 72 格、单格 32 m、高程域 186 – 812 m 的地形；必须包含边界分水岭构造与东南单出口豁口，使全域汇流收敛到唯一出口。片元光照所需的法线必须由高度场的解析梯度与程序化切空间共同得出（禁止使用单张法线贴图或均匀法线）。
- **S2 洼地填平与流向拓扑**：以最小堆优先泛洪填平内部洼地，得到"填平面"；在填平面上按八邻域最陡下降定向，得到流向场。**必须同时保留"未填平"的分叉口径**，两套流向都要可切换、可对比。
- **S3 汇流累积与河网提取**：在流向场的有向无环图上按拓扑序递推汇流累积量；以可调阈值筛出河道并统计河网总长；支持由任意格点向上游反查其产流面（用于溯源高亮）。
- **S4 太阳几何与自遮蔽**：由太阳方位角与高度角计算单格入射一致性；沿太阳水平投影方向步进采样邻坡地平线，得到该格的**自遮蔽上限仰角**，并据此扣减直射；叠加半球环境补光后输出净辐射（W/m²）。方位角与高度角任一变化都必须触发全域重算，禁止只重画光照高光。
- **S5 出口连通淹没推演**：水面**不得**用"高程低于水位即淹没"逐格判定；必须从主出口出发做四邻域连通扩展，被垭口隔断的孤立洼地一律不计入水面，并据此实时结算淹没面积、淹没体积与岸线长度。此外维护一个**在本次会话内只增不减**的"峰值水位包络"账本量（该包络由 `reset()` 清零，此后在同一次会话里只增不减；换一帧重新 `reset()` 后从 0 重新累积，故不同帧的包络值互不相干）。水位是**相对流域最低点**（本 DEM 为 186 m）的抬升量，故水面绝对高程 = 186 m + 水位；凡涉及"某格是否在水下"的比较，两侧必须换算到同一绝对高程口径后再比较，禁止把绝对地面高程与相对水位直接并列。
- **S6 落点两阶段账本**：见第 4 层，需维护暂存候选、已固化测点、确认次数与拒绝次数四类状态，并写入结算账本。
**对冲双指标**（必须成对出现在同一面板）：淹没面积 ↔ 岸线长度（同一水位下两者不同台阶地跳变）；净辐射均值 ↔ 山脊与谷底净辐射之差（自遮蔽越强，两者越反向）；汇流累积量 ↔ 坡度（构成侵蚀风险指数的一对因子）。
**非线性法则**：可调阈值与河网总长之间必须是非线性（对数型）映射，低阈值段河道长度增长远快于高阈值段；淹没面积相对水位必须是**阶跃**而非线性。

## 第 4 层 · 行为因果回路与反直觉陷阱
**复合手势（≥ 5 种，全部必须真实改变可观察状态）**：
1. 左键拖拽 → 轨道相机：以球坐标逐帧重算相机位置并重算视图矩阵，光照高光随视线平滑移动；
2. 滚轮 → 距离缩放：映射必须是指数型（近端细、远端粗），并钳制在距离下限与上限之间；
3. 右键拖拽 → 视点平移：沿相机右向与世界上方向平移视点并同步重算视图矩阵；
4. **Alt + 点击 → 落点第一阶段**：仅把命中格写入暂存候选，绘制橙色候选环；
5. **Enter / 「确认落点」按钮 → 落点第二阶段**：把暂存候选固化为测点；
6. **Esc / 「放弃候选」按钮 → 撤销暂存**：清空候选，确认与拒绝计数均不变；
7. Shift + 拖拽 → 画剖面：拖拽期间的位移必须超过一道显著阈值才允许提交；
8. 双击 → 朝命中点做相机补间飞行；
9. ↑ / ↓ → 修改目标水位，当前水位以固定速率逼近；
10. 空格 → 切换日照连续扫掠。
**两阶段确认（硬要求）**：落测点必须严格两阶段。第一阶段只允许写入暂存候选并绘制候选环，此时：状态机**不得**进入 BASIN_TRACE、集水区高亮**不得**打开、统计面板与账本数值**不得**变化；只有第二阶段固化后才允许上述副作用发生。任何"一次点击直接落点"的实现视为核心机制未实现。
**失败重试闭环（硬要求）**：第一阶段暂存时必须做环境校验——若候选格点位于当前水面以下（该格已被出口连通淹没覆盖），则判定失败：清空暂存、拒绝计数 +1、在面板上给出可读的拒绝原因与"请重选"提示，并要求用户重新执行第一阶段。拒绝不得改变状态机、不得写入账本以外的任何统计。
**反直觉阻尼规则（≥ 3 条，必须可由面板读数验证）**：
- **跃变而非线性**：水位自 210 m 提升到 215 m 时，淹没面积由 1.31 km² 阶跃到 2.17 km²、淹没格数由 1278 格阶跃到 2118 格、岸线长度跳到 7.936 km。淹没面积必须由出口连通性推演得到，用"高程低于水位"逐格判定会把孤立洼地错误计入，面积将不再阶跃。
- **峰值与最陡不重合**：流域侵蚀风险指数的峰值出现在坡度 19.5° 的格点，而全流域最大坡度为 46.8°。指数必须同时体现汇流供给与坡度搬运能力；只取最大坡度格作为峰值即判错。
- **填洼是全域拓扑改写，不是局部修补**：开启填洼后主出口汇流为 2,355 格，关闭后仅 275 格，相差近一个数量级。两套流向口径必须同时保留并在同一条面板行内可读（"主出口汇流 N 格 · 未填洼 M 格"）。
- **阈值与长度反向**：河网提取阈值由 120 格降到 60 格，河网总长由 8.42 km 增至 13.44 km。阈值越高河道越短，滑杆必须实时重算，禁止按比例线性外推。
- **暂存不产生副作用**：第一阶段暂存期间，状态机、集水区高亮、统计与账本一律不动；这是最容易被写成"点击即生效"的地方。
**两阶段与重试的读数出口**：面板必须常驻显示「落点阶段」的三种取值为 空闲 / 待确认 / 已固化，以及「确认 N 次 · 拒绝 N 次 · 暂存 X-Y · 测点 X-Y」的计数行；被拒绝时同一区域必须出现包含"拒绝"字样与具体原因的提示文本。

## 第 5 层 · 技术边界与绝对禁止项
- 全站为**单个自包含 HTML**，CSS 与 JavaScript 必须全部内联；**禁止**任何外部依赖、CDN、网络请求、字体外链。
- **禁止 iframe / srcdoc**；**禁止** `<img>`、内联位图、Base64 图片、`url(data:...)` 贴图；**禁止** `<script src>`、`<link rel=stylesheet>`、`@import`、绝对路径与 `file://`。
- 三维必须走**纯原生 WebGL**：只能使用浏览器原生的 WebGL 上下文，**禁止** Three.js / Babylon.js / PlayCanvas 等任何 3D 引擎，**禁止** gl-matrix 等数学库，**禁止**用二维画布做线框投影冒充三维。
- 必须用 `Float32Array` **手写**模型矩阵、LookAt 视图矩阵与透视投影矩阵，并以矩阵 uniform 传入自写的 GLSL 顶点着色器；片元着色器内必须实现漫反射、Blinn-Phong 高光与随光源距离单调衰减的衰减项组成的**双光源**（一盏固定天光补光 + 一盏跟随太阳方位/高度角的太阳光，低角度时太阳光必须自然转暖），并叠加半球环境光、边缘光与距离雾。
- 相机拖拽必须**逐帧**重算视图矩阵；静止不更新的静态贴图直接判 0。
- **确定性铁律**：禁止任何运行时不确定性——不得使用时间戳、性能计时器、未固定种子的随机数发生器。所有程序化几何与噪声必须由固定种子 `20260925` 的确定性函数生成，同一条控制态向量必须得到同一帧像素。
- 控制台必须 **0 未捕获异常、0 error**；1280 × 720 视口下必须可启动、主画面可见、无横向溢出，两侧面板不得相互压盖或溢出上下边界。
- 面板数值禁止写死：集水面积、最大汇流、河网总长、淹没面积、岸线长度、净辐射三值、侵蚀峰值坡度、全流域最大坡度、落点计数，全部必须来自当局实时结构。

## 全局必显项 · W 控制态向量
画面必须常驻一条 W 控制态向量快照，逐项以「名称=值」成对呈现，且随交互实时刷新：
指标、水位、阈值、方位、高度、填洼、扫掠、环绕、悬停、暂存、测点、剖面、账本、落点阶段、T、步进、图层（逐个列出已启用的图层中文名）。缺任意一项视为信息缺失。

## 交互契约
- `reset()` 之后画面必须回到 T=0、步进=0、八态兜底前的标定态，且暂存/测点/剖面/账本/计数全部清零；
- 存在一组"推进时间"的入口，使画面成为控制态向量的函数；同一控制态向量下重复上屏必须逐像素一致，且与到达该状态的历史路径无关；
- 悬停、拾取、暂存、固化、放弃、剖面、水位、扫掠、账本都必须同时具备"真实鼠标/键盘事件"与"可被自动化调用的等价入口"；
- 相机的 5 个取景预设（西南俯瞰 / 正南纵览 / 东南低角 / 沿谷低角 / 俯视平面）必须真实补间到目标视角，而非瞬时跳变。

【帧间关系声明】
下列八组读数各自属于一个**独立复位后的规范状态**，逐帧建立顺序固定为「`reset()` → 推进到该帧的 T → 施加该帧控制态 → 冻结」。因此：
- 每帧的「落点阶段 / 确认 N 次 / 拒绝 N 次 / 暂存 / 测点」只反映**该帧自己在 `reset()` 之后**发生的落点事件。img_004 的「确认 1 次」对应它这一帧固化的测点 13-7，img_008 的「确认 1 次」对应它这一帧固化的测点 61-14；两帧测点不同并非同一次会话里换了测点，而是两次冷启动各自固化了一个测点。
- 每帧的「峰值水位包络」只反映**该帧自己**推过的最高水位。img_006 这一帧水位停在 215 m，故包络 = 215 m；img_007 这一帧先把水位推到 300 m 再回落到 0 m，包络作为"本次会话内只增不减"的量保留 300 m；img_008 这一帧从未抬升水位，故包络 = 0 m。
- 每帧左侧统计卡与账本必须按**该帧当前**的 DEM / 水位 / 阈值 / 测点实时重算，禁止跨帧复用任何缓存值。
- img_007 的坡度图例刻度串必须完整呈现 46 / 37 / 28 / 18 / 9 / 0 六个刻度，且**末端 0 刻度必须落在图例条高度以内，不得被下方分组标题压住或被裁切**。
